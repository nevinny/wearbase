# Видео → кадры → разбор нужных моментов

Двухуровневый разбор, чтобы не жечь контекст: **дешёвый триаж по контактным листам** находит
*когда*, потом **полноразмерные стоп-кадры** дают *что именно* на экране. Читать все кадры
подряд нельзя — 30-минутное видео при интервале 3 сек = ~600 кадров.

## Шаги

1. **Нарезка** (idempotent, повторный запуск не перекачивает и не перенарезает):
   ```sh
   bash .claude/skills/vid-frames/grab.sh '<URL|файл>' 3
   ```
   Аргументы: источник, интервал в секундах (по умолчанию 3), опц. outdir.
   На выходе — `$OUT/frames/f0001.jpg…` (960px), `$OUT/sheets/s001.jpg…` (сетка 5×5 = 25 кадров
   на лист) и `MANIFEST.md` с формулой «ячейка листа → таймкод». Скачивание 30-минутного видео —
   минуты, запускать `run_in_background` и не ждать вслепую.

2. **Триаж — дешёвыми агентами, а не самому.** Листы делить пачками по ~5 на агента и запускать
   параллельно **в одном блоке**: `Agent(subagent_type: "general-purpose", model: "haiku")`.
   Промпт агенту (подставить, что ищем):
   > Посмотри листы `$OUT/sheets/s001.jpg … s005.jpg` (Read по каждому). Это контактные листы
   > кадров видео: сетка 5×5, порядок построчный. Ищи кадры, где **<ЧТО ИЩЕМ>**.
   > Верни JSON: `[{"sheet": 3, "region": "верхняя|средняя|нижняя треть", "cells": "прибл. номера
   > ячеек", "what": "что видно"}]`. Точный номер ячейки не важен — важен лист и область.
   > Ничего не нашёл — верни `[]`. Не пиши ничего кроме JSON.

   ⚠️ Мелкие модели **путают номера ячеек в сетке** — поэтому и просим область, а не точную
   ячейку. Дальше область → окно времени по формуле из `MANIFEST.md` (± пара кадров), а не
   в одну точку.

3. **Полноразмерные стоп-кадры** по найденным окнам — только их и читать самому:
   ```sh
   bash .claude/skills/vid-frames/still.sh "$OUT/video.mp4" "$OUT/stills" 372 375 378
   ```
   Разумный бюджет — 10–20 стоп-кадров на видео. Нужен зум в угол экрана — резать кадр
   `-vf crop=` вручную, но обычно 1080p-стопкадра хватает.

4. **Вывод** — сразу в `docs/` (правило «фиксация знаний»), в ответе — ссылка на файл и
   таймкоды `mm:ss`, чтобы можно было проверить глазами. Формат таймкода в ответе — от начала
   видео, не номер кадра.

5. **Убрать за собой:** `rm -rf "$OUT"` (видео + 600 кадров ≈ 150–250 МБ). Если разбор будет
   продолжен — оставить и сказать путь в ответе.

## Грабли

- Homebrew-ffmpeg **без drawtext**, ImageMagick не установлен → таймкод в кадр не выжигается,
  считается по формуле из `MANIFEST.md`. Не выдумывать таймкод «на глаз» по листу.
- `tile` в ffmpeg **выбрасывает неполную последнюю плитку** — `grab.sh` добивает её копиями
  последнего кадра (сколько именно — написано в манифесте), так что хвост видео не теряется.
- 960px browse-кадра **не хватает** прочитать имена файлов моделей / значения виджетов в UI —
  для этого только `still.sh`. Не пытаться угадывать мелкий текст по листу.
- Интервал 3 сек — дефолт для скринкастов. Динамичное видео (нарезка, реклама) — 1–2 сек;
  лекция с говорящей головой — 5–10 сек, иначе платим за 600 одинаковых кадров.
