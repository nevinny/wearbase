# ТЗ: Content SEO Engine для coffeeproservice.ru

**Тип:** spin-off RAG-конвейера WEARBASE (отдельный проект, своя кодовая база).
**Цель:** автоматическая генерация **grounded** (на реальных фактах) SEO-статей для блога сайта по ремонту профессиональных кофемашин, с **ручным экспортом** готового контента (markdown/HTML + meta), без интеграции с CMS.
**Рынок/язык:** только РФ / русский.
**Статус:** проверено PoC (см. §2) — путь рабочий. Этот документ — для реализации другим разработчиком/агентом.

---

## 1. Контекст и почему именно так

WEARBASE — каталог брендов: генерит **страницу на сущность** (бренд), grounded на скрейпе. coffeeproservice — другой кейс: **один сайт**, нужны **статьи под ключевые запросы** ниши «ремонт/обслуживание профессиональных кофемашин».

Сайт клиента уже структурирован по брендам кофемашин:
`/service/remont-saeco`, `remont-jura`, `remont-wmf`, `remont-bosch`, `remont-delonghi`, `remont-philips`, `remont-krups`, `remont-siemens`, `remont-necta`, `remont-jofemar`, `remont-kofejnyh-avtomatov`, `diagnostika-...` + `/blog`.

→ Темы статей = **бренд × симптом/узел/код ошибки** (длиннохвостые запросы): «Saeco не набирает воду», «Jura ошибка 8», «замена заварочного узла WMF», «декальцинация Necta» и т.п.

**Ключевое ограничение ниши:** слепой веб-поиск по общим фразам даёт мусор («ремонт кофемашин» → ремонт квартир). Запросы и поиск источников ДОЛЖНЫ быть бренд-уточнёнными.

---

## 2. PoC (доказано в рамках исследования — эталон)

Прогон вручную для темы **«Кофемашина Saeco не набирает воду: причины и ремонт»**:

1. **Поиск источников** (надёжный поиск, не голый SearXNG) → 3 авторитетных статьи (onkofe.com/remont/saeco, remontano.ru, tabera.ru).
2. **Извлечение фактов**: `trafilatura -u <url>` → ~25 000 симв. чистого текста.
3. **Генерация**: локальная `qwen3.5:27b` (ollama, thinking off), system-промпт «эксперт сервиса, пиши СТРОГО из фактов, не выдумывай, без цен/телефонов», temperature 0.4.
4. **Результат**: экспертная статья с реальной конкретикой — коды ошибок Saeco (Error 05–14), SBS-регулятор на Exprelia/Xelsis, поплавок/датчик уровня, декальцинация, варочная группа; структура H1 / Причины / Что сам / Когда мастер; + `META_TITLE`, `META_DESCRIPTION`, 3× FAQ. **Публикабельно.**

Полный пример выхода — §13.

**Вывод:** связка `надёжный поиск → trafilatura → grounded 27b → экспорт` работает на этой нише. Узкое место не в архитектуре, а в **качестве источников поиска** (см. §8).

## 3. Архитектура

```
[список тем]  →  Discover (поиск авторит. источников по теме)
                      ↓
                 Fetch (trafilatura → чистый текст, дедуп, кеш)
                      ↓
                 Build context (top-k релевантных фрагментов; опц. эмбеддинги)
                      ↓
                 Generate (LLM 27b, grounded-промпт) → статья + meta + FAQ
                      ↓
                 Validate (gate качества + SEO-проверки)
                      ↓
                 Export (markdown/HTML + meta, по теме → папка/zip)
```

**AI-узел (переиспользовать существующий):** сервер `192.168.2.43` — ollama (`qwen3.5:27b` генерация, `qwen3-embedding`/`bge-m3` эмбеддинги), trafilatura, опц. Qdrant. Доступ по REST.

**Что переиспользовать из WEARBASE (как образец/код):**
- `WebScraperService` — fetch + trafilatura (fallback DomCrawler), кеш.
- `LlmService` — вызов ollama, `extractJson`, grounded-ветка промпта (`?string $context`).
- Идея **gate качества** из `BrandRagService` (chunks≥N И score≥порог → иначе не генерим).
- `EmbeddingService`/`VectorStoreService` — если делаем retrieval (опционально для длинных корпусов).
- `KeywordService`/`WordstatClient` — частотность тем (Wordstat), приоритизация.

## 4. Пайплайн (детально по стадиям)

### 4.1 Источник тем (вход)
- На вход: `project = { domain, market=ru, topics[] }`, где `topic = { brand, query, intent }`.
- Темы формируются: (а) из структуры сайта клиента (бренды), (б) из Wordstat (частотные «<бренд> кофемашина <симптом>», «<бренд> ошибка <код>»), (в) ручной список.
- На MVP — статический список тем (YAML/CSV), без авто-генерации семантики.

### 4.2 Discover (поиск источников)
- На каждую тему — поисковый запрос **с дизамбигуацией** (обязательно «кофемашина» + бренд), напр. `Saeco кофемашина не набирает воду причины`.
- Источник поиска (по приоритету надёжности — см. §8):
  1. **Курируемый seed-список** авторитетных доменов ниши (мануалы производителей, профильные сервис-сайты/форумы, базы кодов ошибок) — лучший для качества;
  2. поисковый API (Google через рабочий канал / Yandex через XMLRiver — см. §8);
  3. страницы самого клиента (для тона/внутренней перелинковки — НЕ как факт-источник).
- Фильтр: исключить маркетплейсы/агрегаторы-витрины, мусор, дубли доменов. Отобрать 3–6 релевантных URL на тему.

### 4.3 Fetch
- `trafilatura -u <url>` (markdown, `--include-tables` для таблиц кодов ошибок/размеров). Fallback DomCrawler.
- Кеш по url-hash (30 дней). Лимит размера, таймауты, UA как у браузера.
- Отсев пустых/мусорных (мало текста, не про тему).

### 4.4 Build context
- Конкатенация очищенного текста источников; обрезка до ~12–14k симв. (контекст 27b).
- Опционально (если источников много/длинные): чанкинг + эмбеддинги + retrieval top-k по запросу темы (Qdrant). Для MVP достаточно простой конкатенации топ-источников.

### 4.5 Generate
- ollama `qwen3.5:27b`, `think:false`, temperature ~0.4.
- **System**: «технический эксперт сервиса по ремонту проф. кофемашин. Пиши SEO-статью СТРОГО из приведённых фактов. Ничего не выдумывай. Без цен и телефонов. Экспертный тон. Русский.»
- **Структура вывода (фикс):** `# H1`; вступление; «Причины» (маркир. список); «Что можно сделать самостоятельно» (нумер.); «Когда нужен мастер»; затем `META_TITLE:` (≤60), `META_DESCRIPTION:` (≤155), 3× `FAQ_Q/FAQ_A`.
- Ретраи при невалидном выходе (нет meta/структуры) — до 3.

### 4.6 Validate (gate)
- **Grounding-gate**: если по теме корпус слабый (мало/нерелевантные источники) — НЕ генерить (помечать `deferred`), а не лить «воду». Это анти-галлюцинация и анти-SpamBrain.
- SEO-проверки: длина meta_title/description, наличие H1, минимальный объём, отсутствие выдуманных цифр/кодов (по возможности — сверка с источником).
- Уникальность: не копипаст источников (LLM перефразирует; проверять на близость к источнику).

### 4.7 Export
- На тему → файл(ы): `slug.md` с YAML-frontmatter (`title, meta_title, meta_description, h1, faq[], sources[], generated_at`) + тело (markdown), и/или `slug.html`.
- Папка проекта `out/<domain>/<slug>/` или единый zip. FAQ — отдельно как JSON-LD (`FAQPage`) для вставки.
- Никакой автопубликации (по решению заказчика — экспорт ручной).

## 5. Модель данных (минимум)

| Сущность | Поля |
|---|---|
| `Project` | id, domain, market, created_at |
| `Topic` | id, project_id, brand, query, intent, status (`new/discovered/fetched/generated/deferred/exported/failed`), slug |
| `Source` | id, topic_id, url, url_hash, fetched_at, text, ok |
| `Article` | id, topic_id, h1, body_md, meta_title, meta_description, faq_json, grounded(bool), score, created_at |

Хранилище: PostgreSQL/MySQL или даже SQLite для MVP (объём небольшой). Корпус — текст (легковесно).

## 6. SEO-требования (критично — иначе вред, а не польза)

- **E-E-A-T**: тон эксперта-ремонтника; на статьях — автор/сервис, опыт; ссылки на источники (опц.). Контент должен реально помогать (коды, шаги), а не быть «водой».
- **Анти-SpamBrain / scaled content abuse**: Google с 2024 банит масс-генерёный тонкий AI-контент. Защита = **grounding-gate** (нет фактов → не публикуем) + реальная польза + умеренный темп публикации, не «1000 статей за день».
- **Структура**: один H1, логичные H2, FAQ-блок (FAQPage JSON-LD), внутренняя перелинковка на сервисные страницы бренда (`/service/remont-saeco`).
- **Meta**: уникальные title (≤60)/description (≤155) под запрос темы.
- **Без галлюцинаций цен/гарантий/телефонов** (юридически и для доверия).

- Извлечение: trafilatura (CLI, venv).
- Поиск: см. §8.
- Эмбеддинги (опц.): ollama `bge-m3`/`qwen3-embedding` + Qdrant `:6333`.

## 8. Источники поиска — ВАЖНОЕ ограничение (из исследования)

- **SearXNG на сервере** сейчас деградирован (большинство движков банят datacenter-IP). Google поднят через прокси-егресс (мобильный канал), но это инфра WEARBASE — для spin-off лучше **не зависеть** от неё.
- **Yandex скрейпить нельзя** (SmartCaptcha `showcaptchafast` даже через мобильный IP) — только через API (XMLRiver ~₽15/1000, или офиц. Yandex Search API ~₽360–480/1000).
- **Рекомендация для контент-движка:** не полагаться на слепой open-web поиск. Использовать:
  1. **курируемый seed-список** авторитетных доменов ниши (составить вручную: сайты производителей Jura/Saeco/WMF/Necta, профильные форумы, базы кодов ошибок) — самый чистый корпус;
  2. поисковый API (Google SerpAPI / XMLRiver для Yandex) для дозабора по теме — платно, по решению заказчика.
- Для узкой ниши глубина по нескольким хорошим источникам важнее широкого поиска.

## 9. Этапы реализации

1. **MVP (вертикальный срез):** статический список из ~10 тем (Saeco/Jura/WMF × симптомы) → курируемые источники → trafilatura → 27b → экспорт md+meta. Цель: 10 публикабельных статей, ручная проверка качества.
2. **Семантика:** Wordstat-приоритизация тем, расширение списка по всем брендам клиента.
3. **Gate и валидация:** grounding-gate, SEO-чек, антидубликат.
4. **Масштаб + retrieval:** эмбеддинги/Qdrant для длинных корпусов, батч-прогон, отчётность.
5. (опц.) Полу-авто публикация, если заказчик передумает про ручной экспорт.

---

## 10. Критерии приёмки (MVP)

- [ ] 10 тем → 10 статей, экспорт в `out/`.
- [ ] Каждая статья: H1 + 3 раздела + meta_title/description + 3 FAQ.
- [ ] Контент grounded: факты (коды/узлы/шаги) сверяемы с источниками, без выдумок.
- [ ] Тема без нормальных источников → `deferred`, статья НЕ генерится (gate работает).
- [ ] Уникальность: не копипаст (перефраз), meta уникальны.
- [ ] Запросы дизамбигуированы (бренд+«кофемашина») — нет мусорных источников.

---

## 11. Риски

| Риск | Защита |
|---|---|
| Галлюцинации LLM | grounded-промпт + gate + сверка фактов |
| SpamBrain-фильтр за масс-AI | реальная польза, grounding, умеренный темп, E-E-A-T |
| Мусорные источники (общие фразы) | бренд-дизамбигуация запросов + курируемый seed |
| Зависимость от чужой инфры (SearXNG/прокси) | seed-список + свой поисковый API |
| Дубли/неуникальность | перефраз + проверка близости к источнику |

## 12. Что НЕ входит
- Автопубликация в CMS (экспорт ручной).
- Не-RU рынки/языки.
- Технический SEO-аудит сайта (отдельная задача).

## 13. Пример выхода (PoC, эталон качества)

Тема: **«Кофемашина Saeco не набирает воду: причины и ремонт»**

> # Кофемашина Saeco не набирает воду: причины и ремонт
>
> Если кофемашина Saeco перестала подавать воду или на дисплее загорелась ошибка, это часто указывает на проблемы с гидросистемой, засоры или неисправность датчиков. …
>
> ## Причины
> - Засорение фильтров и магистралей; накипь в водяном контуре.
> - Неисправность датчиков уровня воды (поплавок/электромагнитный датчик; засор контактов, деформация от горячей воды).
> - Воздушная пробка; повреждение уплотнительного кольца резервуара; поломка поршневого насоса; сбои электроники; неверная установка узлов.
>
> ## Что можно сделать самостоятельно
> 1. Проверить резервуар и его установку; прогнать воду.
> 2. Декальцинация, очистка фильтра. 3. Удалить воздушную пробку через краник/капучинатор. 4. Проверить поплавок. 5. Очистить варочную группу/воронку. 6. Перезагрузить (отключить от сети). …
>
> ## Когда нужен мастер
> - Error 06 (мультиклапан), 07 (капучинатор), 08 (плата), 09–14 (датчики/нагреватели), 13 (водонагреватель); сложные засоры; повторение ошибок. …
>
> META_TITLE: Кофемашина Saeco не набирает воду: причины и ремонт
> META_DESCRIPTION: Кофемашина Saeco не набирает воду: коды ошибок, причины засоров и поломки датчиков. Инструкция по диагностике.
> FAQ: Error 05 (блокировка контура/воздух/накипь → декальцинация, SBS на Exprelia/Xelsis); «не видит воду при полном баке» (поплавок/датчик/уплотнитель); «чистка трубок» (стыки — да, трубки — к мастеру).
