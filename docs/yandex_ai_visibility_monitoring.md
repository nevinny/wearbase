## Недельный чек-лист (пятница/понедельник, ~10 мин — шаг 1 автоматизирован)

Ручной прогон: `php -d memory_limit=512M bin/console app:seo:gap-report --stdout-only` (опции `--source=yandex|gsc|both`, `--min-shows`, `--limit`, `--json` для полного дампа).

3. **Классифицировать по интенту** — теперь делает `app:seo:gap-report` сам (группы ниже — это и есть его группировка, не отдельный ручной шаг).

   - **brand_entity** («X чей бренд», «что за бренд X», «X какой страны») → проверить, что `app:seo:aio-remediate` отработал по этой карточке (блок FAQ «Что за бренд X?»); если нет — прогнать точечно.

   - **geo_category** («бренды одежды спб») → **непокрыто**, нужна лендинг-страница категории/гео (см. ниже). Гео-паттерн сейчас — спб/петербург/москва (стартовый список из реальных данных); расширять по мере появления новых городов.
   - **replace_comparison** («uset это uniqlo», «чем заменить Zara») → листикл `app:seo:replace-listicle`.
5. **Тренд неделя-к-неделе** — теперь в таблице `seo_gap_snapshot` (одна строка на `source`+`intent_group` за каждый прогон, `ON DUPLICATE KEY UPDATE`), а не в running-лог вручную:
   ```
   php -d memory_limit=512M bin/console dbal:run-sql "SELECT captured_on, source, intent_group, gap_count, top_query FROM seo_gap_snapshot ORDER BY captured_on DESC"
   ```

## Связь со стратегией

Это **мониторинг, а не контент-пуш.** Согласуется с выводом «контент в ширину ≠ рычаг роста» (память `content-not-growth-lever`): цикл (а) валидирует, что `aio-remediate` реально закрывает brand_entity-дыры, (б) вскрывает две узкие, дешёвые точки — гео-СПб посадочная и навигационные карточки на pos ~10.5. Net-new сигнал = SoV в Алисе AI, которого у нас в данных пока нет.
