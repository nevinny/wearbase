# getwifi.com как эталон директории: цифры, потолки, сверка с RAG

Разбор от 2026-07-21. Вопрос владельца: getwifi уже даёт трафик — нужен ли RAG-конвейер
WEARBASE, чтобы повторить заработок, или можно без него. Ответ выведен из фактических выгрузок
GSC getwifi.com + сверен с базой знаний (`topic_chunks`: [[freychu-directory-playbook]] +
DrMax SEO, см. [directory_playbook_freychu.md](directory_playbook_freychu.md)).

## Что такое getwifi (факт)
Программатик-директория Wi-Fi-точек из **OpenStreetMap** (бесплатный ODbL-фид) + жёсткая
SEO-дисциплина (`docs/page-types-matrix.md`: doorway-пороги `HAVING COUNT ≥ 3/5`, hold-first
локали, canonical/sitemap). Контент генерится **шаблонами из данных, без единого вызова LLM**.
Монетизация: AdSense (+ виджет GetRentaCar), подключён только в июле 2026 → выручка ранняя.

## Цифры GSC (3 мес, срез ~2026-07)
| Метрика | Значение |
|---|---|
| Клики / показы | **1 903 / 64 010** (моб. 90%), средняя позиция ~7 |
| Динамика показов | **85/день → 2 181/день за 6 недель** (растёт ~линейно) |
| Индексация | **3 027 из ~10 020 (~30%)** |
| «Обнаружена, не проиндексирована» | **6 837** страниц |
| Брендовый трафик | главная 921 клик; топ-запросы `getwifi`, `getwifi.no`… |

**Читается так:** фид+шаблоны+SEO реально дают дешёвый растущий трафик (тезис владельца
подтверждён). НО:
- **~половина кликов — брендовые**, причём часть — перехват чужого бренда **getwifi.no**
  (норвежский Wi-Fi-сервис; getwifi.com на позиции 4.8 = ниже настоящего). Это не заслуга
  директории. Чистого директорийного лонг-тейла ~980 кликов/3мес (~11/день, растёт).

## Два потолка тонкой программатик-директории (вживую)
1. **Стена индексации.** 6 837 «discovered, not indexed» = фильтр тонкого/scaled-контента:
   Google обошёл и решил не индексировать 68% сайта. Больше страниц ≠ больше трафика.
2. **Стена CTR.** Экспонат: `/wifi/other/planet-fitness-us` — **13 476 показов, 69 кликов,
   CTR 0.51%**, позиция 6.66. Страница ранжируется, но не отвечает на интент (нужен *пароль*,
   его на странице нет) → клик не выигрывается.

## Сверка с RAG (что база подтверждает и что уточняет)
Оба независимых источника подтверждают диагноз, но **удешевляют** лечение:

**Подтверждают:**
- Обогащение = ров. Frey Chu: «make your directory more valuable… nuance within the niche».
  DrMax (`Entity-Gap Analyzer`): «большинство старых страниц страдают от **дефицита сущностей**»;
  «внутренние инсайты (отзывы, sales calls) — **конкурентам сложнее скопировать**».
- «Discovered, not indexed» ↔ дефицит сущностей / HCU (DrMax: E-E-A-T/HCU-аудит).
- Дизайн переоценён (Frey Chu: «design doesn't move the needle… mobile matters»). Проблема
  getwifi не в вёрстке.
- Swap-backlink (verbatim): «$50 to **swap** out the link… not to add mine, but to swap it».

**Уточняют (правка к первому ответу):**
1. **«Обогащение» ≠ «прогнать конвейер».** У Frey Chu enrichment — это *недостающий факт под
   запрос* (пароль; towing-capacity по модели; «кремируют ли тут лошадь»), часто программатик/
   AI по отзывам — **не длинная генерённая проза**. Для getwifi достаточно положить сам пароль/
   шаги — дешевле и точнее, чем тяжёлый брендовый RAG.
2. **Порог монетизации выше «есть трафик».** Frey Chu: Mediavine — от 50k сессий; ниже —
   AdSense/Journey. Его же 70–90k визитов/мес = всего **$2–3k/мес**. «getwifi-уровень» на
   зрелости — скромный; ожидания трезвые.
3. **Брендовые ключи бесполезны** (Frey Chu: «stay away from branded keywords»). Подтверждает:
   getwifi.no-путаница — не модель.
4. **Бонус-рычаг (DrMax):** hub-архитектура + Page Types (сравнения/глоссарии/решения) +
   перелинковка — конкретный способ проталкивать «discovered» в индекс. У getwifi
   page-type-matrix есть → не хватает hub/кластеров и внутренних ссылок.

## Матрица: датум-обогащение vs RAG-конвейер
| Ось | Фид + шаблоны + датум | RAG-конвейер (grounded-проза) |
|---|---|---|
| Когда | Есть чистый структурный фид (OSM, API, дамп); ответ = 1 факт | Нет фида; ценность = нарратив/сущности/история |
| Пример | getwifi (Wi-Fi), dry-ice, локации, towing-capacity | WEARBASE (бренды: факты размазаны по вебу) |
| Стоимость | ≈0, программатик | дорого (discover→fetch→embed→generate на GPU) |
| Что ломает | стену CTR (кладёт недостающий факт) | обе стены (уникальный entity-rich контент) |
| Риск | тонкость → деиндекс, если факт не положить | оверкилл на data-heavy нишах; следить за «discovered» |

**Вывод:** конвейер — **не двигатель трафика, а таран против потолков**, и оправдан только там,
где контент реально нарративный. WEARBASE (бренды) в этом квадранте → конвейер = differentiator.
getwifi (data-heavy) → конвейер оверкилл, хватит датума.

## Что делать (по убыванию дешевизны)
1. **getwifi:** обогащать **уже индексированные** 3 027 страниц недостающим фактом под CTR
   (математика: `planet-fitness` при CTR 0.5%→3% = ~400 кликов вместо 69) + hub/перелинковка
   против 6 837 «discovered» + 1–2 swap-беклинка. Новые страницы — НЕ приоритет.
2. **WEARBASE:** держать конвейер как ров только для брендов; монетизировать существующий
   трафик РСЯ/AdSense параллельно; **следить за метрикой «discovered, not indexed»** — не
   заливать прод тонкими карточками пачками, иначе получишь getwifi-стену.
3. **Портфель директорий** (Frey Chu/getwifi-плейбук на переиспользуемом каркасе
   page-type-matrix) — расфокус относительно [[focus-directive-first-sale]]; в очередь ПОСЛЕ
   проверки B2B-услуги.

## Правка RAG по ходу разбора
Обнаружено: на общих SEO-запросах **freychu (42 чанка) тонул под drmaxseo (416)** — не всплывал
в top-k вообще. Починено в `AdvisorRag::retrieve`: over-fetch пула (k×5) + **кап на канал**
(`max(2, ⌈k/3⌉)`): pass1 гарантирует слоты малым каналам по score, pass2 добирает до k без капа.
Проверено на реальных данных: было 1 freychu/5 drmax → стало 2 freychu/4 drmax (+ второй
freychu-чанк, которого в старом top-6 не было). Заодно улучшает диверсити для генерации идей.
