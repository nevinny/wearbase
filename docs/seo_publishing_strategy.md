# Стратегия размещения SEO-статей (блог + Дзен)

Как публиковать сгенерированный комплект (`var/seo/blog/*` + `var/seo/dzen/*` +
`var/seo/guides/*`): каналы, последовательность, **частота**, индексация, обратная связь.
Контекст и «почему так» — [dzen_seo_methodology.md](dzen_seo_methodology.md),
[seo_boost.md](seo_boost.md), площадки — [seo_publishing_platforms.md](seo_publishing_platforms.md).

## 1. Каналы и роли

| Канал | Роль | Почему |
|---|---|---|
| **Блог wearbase.ru** (`site`) | **Первоисточник / canonical** | Owned-актив: растит авторитет домена, внутренние ссылки качают карточки брендов, прямой органик, легко автоматизировать (записи `Article`) |
| **Яндекс.Дзен** (`dzen`) | **Вариант для охвата + GEO** | Сильный домен → быстрая индексация/охват, пока блог молодой; бэклинки; цитирование AI. Публикация автоматизирована через RSS «Дзен для сайтов» (см. §6а) |
| Прочие (vc/pikabu/telegra.ph…) | Доп. охват позже | По мере роста; см. seo_publishing_platforms.md |

**Принцип:** блог = дом контента (где живёт canonical), Дзен = арендованный охват (вариант со ссылкой на блог). Не дублировать один текст 1-в-1 — Дзен-версии генерятся другой персоной.

## 2. Последовательность на каждую статью

```
1. Блог (canonical) → опубликовать → Яндекс.Вебмастер «переобход» + GSC → дождаться индексации
2. Дзен-вариант → опубликовать ПОСЛЕ индексации блога, со ссылкой «Первоисточник: wearbase.ru/…»
```
Блог-первым закрепляет твой домен как источник; Дзен (сильный домен) тогда не перебьёт оригинал и не будет зарезан как копия.

## 3. Частота размещения (рекомендация)

**Принципы:** Яндекс и Дзен любят **ровный ритм**, а не залпы. Новый канал, вываливший 38 статей за день, = сигнал контент-фермы (троттлинг) + ничего толком не проиндексируется. Эффект накопительный — раскачка на дистанции 6–12 мес.

| Канал | Темп | Почему |
|---|---|---|
| **Блог** | **1–2 статьи/день** | Свой домен терпит больше, но ровно + чтобы каждая успела попасть в индекс. 38 статей → ~3–4 недели |
| **Дзен** | **1 статья/день** | Новый канал: плавная раскачка, алгоритм Дзена ценит регулярность. Строго после индексации блог-оригинала. 38 → ~5–6 недель |

- Потолок раннего этапа: **не больше 2–3/день на канал**.
- После выкладки стартовых 76 — держать **ровный дрип ~20–30 статей/мес на канал** (методология из видео даёт ~100/мес, но для каталога 20–30 — реалистично и безопасно), подпитывая длинный хвост (новые города, сравнения брендов).

## 4. Порядок выкладки (приоритет по ценности)

1. **Гео-листиклы + гео-гиды (Москва/СПб)** — сильный локально-коммерческий интент («где купить X в городе», «ТОП X города»), меньше конкуренции.
2. **Нишевые гиды** — широкий охват, растят тематический авторитет домена.
3. Остальное по убыванию Wordstat-спроса (ранжир из `app:seo:ranking`).

## 5. Индексация

- **Блог:** Яндекс.Вебмастер «Переобход страниц» (есть суточный лимит) + Google — `app:google:index-ping` (≤200/день) и `app:gsc:sync`. Каждую новую блог-статью отдавать на переобход. Включить блог-URL в sitemap.
- **Дзен:** индексируется Яндексом быстро и сам (это его площадка).

## 6. Closed-loop «блог → индексация → Дзен» (автомат)

Встроено в ежедневный **`app:gsc:sync --report`** (отдельная команда не нужна):
- статья публикуется в блог дрипом (`publishedAt`), `source_file` хранит исходный .md;
- ежедневно `app:gsc:sync` делает URL Inspection блог-статей из конвейера, ещё не
  сигнализированных (`indexed_notified_at IS NULL`, ≤50/прогон);
- как только страница в индексе → в **TG-уведомление** добавляется строка
  «✅ Проиндексирована: «…» → публикуй Дзен-вариант: `<файл>`» и ставится
  `indexed_notified_at` (антиповтор);
- ты публикуешь Дзен-вариант **ровно после реальной индексации** блог-оригинала.

Поля `article`: `source_file`, `indexed_at`, `indexed_notified_at` (миграция
`Version20260625_blog_index_watch`).

⚠️ **Устарело как узкое место**: этот TG-пинг существовал только потому, что публикация
в Дзен была ручной (копипаста). С фидом «Дзен для сайтов» (§6а) Дзен подхватывает статью
сам за 2–5 мин после публикации в блоге — ждать индексацию блога и вручную публиковать
Дзен-вариант больше не нужно для republish-механики. TG-уведомление «✅ Проиндексирована»
из `app:gsc:sync` остаётся полезным как сигнал успеха индексации блога, но перестаёт быть
триггером для ручного действия.

## 6а. Дзен для сайтов — RSS-автопилот (замена ручного плейбука)

Официальный (не серый) механизм: сайт отдаёт RSS-ленту, Дзен сам её поллит и публикует
материалы от привязанного канала — без Zapier/Make-хаков и без API-ключей.

- **Эндпойнт**: `GET /rss/dzen.xml` (`DzenFeedController`, шаблон `templates/rss/dzen.xml.twig`) —
  последние `MAX_ITEMS=30` опубликованных статей блога (RSS 2.0,
  `yandex:full-text`/`content:encoded` = полный HTML `article.content`, `pubDate` из
  `publishedAt`). Отдаёт скользящее окно, а не архив — Дзен не индексирует материалы
  старше 8 дней, окно синхронизировано с блоговым дрипом (1–2/день).
- **Что публикуется**: тот же текст, что и в блоге (не отдельная Дзен-персона из
  `var/seo/dzen/*` — этот генератор/каталог теперь для будущего кастомного контента,
  не для рутинного republish). Дублирование не наказывается: Дзен явно знает, что это
  синдицированный источник, и показывает атрибуцию/ссылку на оригинал.
- **Ручной шаг (один раз)**: привязать домен wearbase.ru / URL фида к каналу WEARBASE в
  кабинете Дзена. После этого конвейер блог→Дзен полностью автоматический.
- ⚠️ **Прогрев канала**: новому каналу нужно ~14 дней плавной раскачки — заливка сразу
  всего бэклога через фид похожа на спам-паттерн. На практике не проблема: блог и так
  дрипует 1–2 статьи/день (§3), фид просто зеркалит этот темп.
- Требования Дзена к фиду (dzen.ru/help): RSS 2.0, UTF-8, ≤10 Мб, отдаётся ≤10 сек;
  title ≤200 симв. без КАПС/точки на конце; опционально category/author/enclosure
  (картинка ≥400×800) — у `Article` пока нет обложки, enclosure не реализован (не
  блокер, картинка опциональна).

## 7. Обратная связь по эффективности

- **Яндекс.Метрика + UTM:** Дзен-ссылки несут `utm_source=dzen&utm_campaign=…` (и отдельная `cta-…`) → видно переходы из Дзена на карточки и каталог. Блог = внутренние переходы, Метрика считает напрямую.
- **GSC/Вебмастер:** позиции блог-статей по целевым запросам.
- **Через месяц:** усиливать то, что зашло (топ-статьи) — генерить больше по выигрышным нишам/городам/форматам; слабое — переписывать (`--variants`/другая персона) или докручивать gap'ы.

## 8. Инструментарий

| Шаг | Инструмент | Статус |
|---|---|---|
| Генерация | `app:seo:listicle` / `app:seo:guide` (P1 + AI-Overview блоки + verify-gate) | ✅ готово |
| Выбор тем по спросу | `app:seo:ranking` (бренд→город, матрица стиль×город) | ✅ готово |
| **Публикация в блог** | **`app:seo:publish-blog`** — `var/seo/blog/*.md` → записи `Article` (canonical, внутренние ссылки), **дрип-расписание** через будущий `publishedAt` (`--per-day=N`, `source_file` для closed-loop) | ✅ готово |
| Индексация блога | `app:google:index-ping`, `app:gsc:sync` + Вебмастер | ✅ есть (переиспользуем) |
| Публикация в Дзен | `GET /rss/dzen.xml` — «Дзен для сайтов» (см. §6а); привязка домена к каналу — разовый ручной шаг | ✅ готово (feed), 📋 привязка канала |
| Мониторинг | Метрика + UTM, GSC, `app:report:daily` | ✅ есть |

### Дрип через `publishedAt` (как работает)
Команда `app:seo:publish-blog` импортирует все статьи сразу, но проставляет
`publishedAt` в будущее с шагом (напр. 1–2/день). Блог показывает статью, когда
`publishedAt <= now` → получаем ровный дрип без ручной работы и без cron-генерации.

### Дзен — ручной плейбук (устарел, см. §6а)
Актуально только пока домен не привязан к каналу в кабинете Дзена, или для разовой
публикации кастомного текста мимо фида (напр. из `var/seo/dzen/*`, другая персона):
1. Взять `var/seo/dzen/<статья>.md` (или `guides/`).
2. Новый пост в канале WEARBASE → вставить текст (markdown Дзен поддерживает частично — проверить заголовки/таблицу/ссылки).
3. Обложка (генерёжка/фотобанк), `alt` с ключами+гео.
4. В конце — ссылка «Первоисточник: <блог-URL>».
5. Опубликовать; отметить дату в трекере для соблюдения 1/день.

## 9. Правовое
Маркировка рекламы (ФЗ-38/ОРД) — там, где это реклама. Наши статьи = редакционные обзоры каталога на реальных фактах (grounded) → для нейтральных обзоров токен обычно не нужен; если бренд платит за место — пометить.
