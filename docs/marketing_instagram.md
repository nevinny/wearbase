## 0. ⚠️ Юридическая рамка (читать первым)

- **Meta Platforms** (Instagram, Facebook) **признана экстремистской и запрещена в РФ** (с 21.03.2022),
  Instagram заблокирован — органический охват в РФ только через VPN.
- **С 01.09.2024 реклама на ресурсах Meta запрещена законом РФ** → **платное продвижение (Ads,
  таргет, реклама у блогеров с оплатой) — НЕЛЬЗЯ.** Только органический постинг.
- Любое упоминание Instagram в РФ-материалах — с дисклеймером: *«принадлежит Meta, признанной
  экстремистской и запрещённой в РФ»* (касается и ссылки в подвале сайта — открытый вопрос в
  [`tasktracker.md`](tasktracker.md)).

**Вывод по архитектуре:** движок автопубликации делаем **канал-агностичным** — один конвейер
генерации контента питает несколько каналов. Приоритет для РФ-аудитории — **Telegram (основной)
+ VK**; Instagram — **вторичный** канал на диаспору/VPN-аудиторию и как витрина бренда.
Этот документ описывает Instagram-постинг, но 90% конвейера (генерация карточек, подписей,
очередь, дрип) переиспользуется для TG/VK без изменений.

## 1. Позиционирование аккаунта

Аккаунт — не «витрина каталога», а **медиа движения «Прямой бренд»** (принцип 4 стратегии:
культура-first, контент = сувенир культуры). Лента ведёт себя как издание про независимые
русские марки, которое заодно их каталогизирует.

**Bio (черновик):**
> Независимые русские бренды одежды. Покупай напрямую у тех, кто это сшил — не у маркетплейса.
> 1000+ марок · #ПрямойБренд
> 👇 каталог и калькулятор «сколько WB забирает у бренда»
> _(дисклеймер Meta — в закрепе/первом сторис)_

Ссылка в шапке → лендинг-хаб (каталог + калькулятор + манифест). Тон: умный друг, которому
надоели маркетплейсы; без sterile-копии и без banned-AI-слов (Часть 0 канона).

## 2. Контент-пиллары (рубрики)

Каждая рубрика привязана к мессединг-пиллару стратегии (§5) и аудитории, и помечена по
авто-генерируемости — это определяет, что реально крутить «в автоматическом режиме».

| Рубрика | Пиллар | Аудитория | Формат | Авто-генерация |
|---|---|---|---|---|
| **Бренд недели** (история основателя) | C/D | shopper+brand | карусель | ⚙️ Полу-авто (данные из RAG-корпуса `brand_chunks` → шаблон; фото бренда нужно) |
| **«Сколько WB забирает у тебя»** (калькулятор-карточка) | B | brand | single/карусель | ✅ Полный авто (числа → шаблон) |
| **Сделано в {город}** / дроп новых брендов | C | shopper | карусель | ✅ Полный авто (новые бренды из БД) |
| **Манифест-цитата / #ПрямойБренд** | A | both | single | ✅ Полный авто (ротация тезисов манифеста) |
| **Напрямую vs маркетплейс** (мифы / before-after) | D | shopper | карусель | ✅ Полный авто (шаблон сравнения) |
| **Reels: faceless / движение** (текст-на-моушене + аудио): манифест, факт о комиссии, подборка | A/B/D | both | Reels | ✅ Полный авто (моушн-шаблон + image-gen фон, текст оверлеем) — см. §5 |
| **Reels: data-motion** (анимация калькулятора/статистики) | B | brand | Reels | ✅ Полный авто (рендер из данных, Remotion/AE-шаблон) — см. §5 |
| **Reels: product-motion** (оживление товарных фото бренда) | C/D | shopper | Reels | ⚙️ Полу-авто (image-to-video из **реальных** фото бренда) — см. §5 |
| **Бренд недели** (история основателя) | C/D | shopper+brand | карусель | ⚙️ Полу-авто (текст из `brand_chunks`; фото от бренда) |
| **Reels: основатель / распаковка** | C/D | shopper | Reels | ❌ Ручной (нужна реальная съёмка) |
| **UGC: бренд с бейджем «Прямой бренд»** (репост) | культура | both | repost/сторис | ❌ Ручной (реальный контент бренда + согласие) |

> С подключением генерации (см. §5) **faceless/data-Reels переходят в ✅ полный авто**, а
> product-Reels — в ⚙️ полу-авто (нужны реальные фото бренда). Что **остаётся ручным и не
> подлежит фейку**: founder talking-head и **UGC** — это контент реальных людей. Синтетический
> «UGC» противоречит самому стержню движения «Прямой бренд» (*люди, которые делают вещи, против
> машины*) и нарушает обязательную маркировку AI-контента Meta → бан/репутационный риск. Правило:
> **AI удешевляет производство контента реальными брендами, а не подменяет его** (Stage-2
> активационной воронки: бейдж + просьба о клипе на Day 0, см. [`marketing_email.md`](marketing_email.md)).

## 3. Недельная сетка + ramp-up (drip)

Дрип-дисциплина = как в SEO: **не заливать пачкой, наращивать постепенно, греть аккаунт.**
Резкий старт нового аккаунта с 5+ постами/день → shadow-ban/спам-флаг.

**Ramp-up (новый аккаунт):**
| Период | Лента (feed) | Stories | Reels |
|---|---|---|---|
| Неделя 1 | 3/нед | 1/день | 0 |
| Недели 2–3 | 4–5/нед | 2–3/день | 1/нед |
| Steady state (нед. 4+) | 1/день (≤7/нед) | 3–5/день | 2–3/нед |

**Жёсткий потолок:** ≤ хард-лимита API (см. §4), де-факто ≤2 поста/день в ленту — больше
вредит охвату (алгоритм «штрафует» частоту). Steady-state сетка:

| День | Рубрика (лента) | Сторис |
|---|---|---|
| Пн | Бренд недели: история основателя (RAG-факты) | тизер бренда + опрос |
| Вт | Demand: ответ на топ-запрос бренда (Wordstat) | подборка + link-стикер |
| Ср | Сделано в {город} / новые дропы | новые бренды + link |
| Чт | Манифест-цитата #ПрямойБренд | цитата + reshare |
| Пт | Чем заменить ушедших (departed_brands.yaml) | подборка + опрос |
| Сб | UGC бренда с бейджем (если есть) | репост сторис бренда |
| Вс | Лайфстайл «нашёл раньше ленты» | подборка-карусель в сторис |

Reels (2–3/нед) ставятся поверх сетки в Вт/Чт/Сб — лучшие слоты по охвату.
Пн/Вт/Пт обновлены Фазой 1 `docs/social_value_plan.md` (save-утилиты для покупателя,
2026-07-13); calculator/vs_marketplace остаются в коде как backing-def для
`SocialPlanner::AUTO_FALLBACK`, из еженедельной сетки выведены.

## 4. Движок автопубликации (pipeline + drip)

Переиспользует паттерны проекта: статус-машина (как `brand_rag_pipeline`), дрип-тик (как
SEO `publish-tick`), QA-гейт (как `ArticleQaService`/`ContentValidator`), closed-loop (как
`app:seo:evaluate-experiments`).

**Конвейер (статус-машина `social_post`):**
```
plan → generate(caption+image) → qa_gate → scheduled → published / failed / held
```
1. **`app:social:plan`** (раз в неделю, cron) — собирает план на 7 дней из источников данных
   (новые бренды, `brand_keyword`, корпус `brand_chunks`, ротация манифеста, числа калькулятора),
   создаёт записи `social_post` в статусе `plan` по сетке §3.
2. **`app:social:generate`** — для каждого `plan`:
   - **caption** — LLM (локальная ollama, как `LlmService`), grounded в фактах бренда; прогон
     через анти-AI-гейт (banned-слова из Часть 0 канона, FRES, first-person ok).
   - **media** — рендер из шаблона (логотип бренда + данные/числа) + опц. image/video-gen для
     Reels (см. §5). Логотип/цифры всегда оверлеем поверх, не «внутри» генерации.
   - статус → `qa_gate`.
3. **QA-гейт** — авто-проверка: нет banned-слов, есть дисклеймер где надо, есть CTA/ссылка,
   ≤ лимита хэштегов, картинка отрендерилась. Провал → `held` (на ручной просмотр), не публикуем.
4. **`app:social:publish-tick`** (ежечасно, cron) — **дрип-публикация**: берёт `scheduled` с
   подошедшим временем, постит через API, соблюдая:
   - **ramp-cap** (см. §3) — N постов/день по неделе аккаунта;
   - **хард-лимит Instagram Content Publishing API: 25 опубликованных медиа / 24ч** (rolling);
   - **health-cap** (аналог GSC-кэпа): если охват/ER рубрики просел или аккаунт флагнут —
     троттлить до ручного ревью.
   - требования к аккаунту (см. §4а): **нужен Professional-аккаунт (Creator достаточно)**;
     **FB-страница БОЛЬШЕ НЕ нужна** — с июля 2024 есть «Instagram API with Instagram Login»
     (прямой логин в IG). ✅ **Реализовано и работает** (первый живой пост 2026-07-18):
     `src/Social/Publisher/InstagramPublisher.php` публикует контейнерным способом
     (`/media` → поллинг `status_code` → `/media_publish`) напрямую на `graph.instagram.com`,
     без Postiz. Посты публикуются немедленно по вызову (нативного «расписания» в API нет —
     держит наш тик). ⚠️ Официальная Meta-интеграция в РФ юридически спорна (см. §0).

**Карусель (2026-07-31).** `InstagramPublisher` умеет карусель: слайды берутся из
`social_post.media_path` (**список путей, по одному на строку** — `SocialPost::getMediaPaths()`,
колонка переведена в TEXT миграцией `Version20260731_social_post_media_paths`). Флоу: на каждый
слайд контейнер с `is_carousel_item=true` (без подписи) → поллинг до FINISHED → родительский
контейнер `media_type=CAROUSEL` + `children=<id,id,…>` + подпись → один `media_publish`.
Лимит IG — 10 слайдов; больше → пост не публикуется с явной ошибкой (слайды не режем молча).
Режим выбирается по числу медиа, не по `media_type`, поэтому одиночная картинка публикуется как
раньше. TG/VK берут первый слайд (`sendMediaGroup`/мульти-фото на стене не поддержаны).
⚠️ Генерация пока кладёт в пост одну картинку — **многослайдовый рендер ещё не сделан**, паблишер
к нему готов.

### 4б. Галереи брендов: карусель + Reels + A/B логотипа (2026-07-31)

Рубрики `brand_gallery` (карусель) и `brand_reels` (слайдшоу) строятся из **реальных фото**
`brand_image`, а не из AI-карточек. Ставятся пачкой: `app:social:enqueue-brand-gallery`
(`--per-day` брендов в день, `--limit`, `--no-reels`, `--dry-run`); дедуп по (канал, бренд,
рубрика) → команду можно гонять повторно, добирает только новые бренды.

- **Гейты бренда:** `status=active`, ниша ≠ `off`, происхождение ≠ `foreign`, ≥2 фото, у которых
  файл реально лежит на диске. На 31.07.2026 прошли **290 брендов** из 331 с фото.
- **Нормализация обязательна** (`GallerySlideRenderer`): все слайды приводятся к 1080×1350
  (вписывание с полями, без обреза — обрез съедает вещь). Instagram кадрирует ВСЮ карусель по
  пропорции первого слайда, поэтому без единого холста (а) часть слайдов резалась бы, (б) A/B
  «логотип первым vs последним» сравнивал бы ещё и разное кадрирование.
- **Слайд логотипа:** фон холста берётся из углового пикселя самого лого (часть логотипов —
  растровые блоки со своей заливкой, на белом они смотрелись серым прямоугольником), цвет текста
  выбирается по яркости фона.
- **Reels** (`ReelsSlideshowRenderer`): те же слайды → ffmpeg → mp4 1080×1920, 2.5с на слайд,
  H.264+AAC (дорожка тишины: трендовое аудио через API легально не приклеить, а совсем без
  аудио контейнер принимается нестабильно). Публикуется контейнером `media_type=REELS` +
  `share_to_feed=true`; поллинг для видео длиннее (30 попыток против 12).
- **A/B:** `social_post.variant` = `logo_first|logo_last`, чередуется по позиции в очереди (50/50),
  карусель и Reels одного бренда получают ОДИН вариант. Результаты — `app:social:evaluate`,
  группировка по (рубрика, вариант).
- **Проверено живьём 30.07.2026:** карусель `instagram.com/p/DbbwKWHDXqZ/` (IG отдаёт
  `CAROUSEL_ALBUM`, 10 слайдов), Reels `instagram.com/reel/DbbwNksAsof/` (27с). Ручной прогон
  конкретного поста вне расписания — `app:social:publish-tick --post=<id>`.

### 4в. Удержание внимания: хук, счётчик, прогресс, темп (2026-07-31)

Первые ~3 секунды решают раздачу Reels, поэтому первый кадр несёт **хук-надпись**
(`SlideHookComposer`). Хук собран НЕ из поисковых фраз Вордстата (запрос описывает намерение
искать, а не удерживает внимание), а по канону: Шварц («копия канализирует существующее
желание», заголовок под уровень осведомлённости → имя незнакомого бренда в хук не ставим),
Чалдини (внимание держат само-релевантное, незавершённое, загадочное → город как якорь),
Лёвенштайн/Зейгарник/Хиты (разрыв в знании открываем и не закрываем), Огилви (конкретика
вместо превосходных степеней). Город подставляется только в именительном падеже (морфологию
не тянем), числительное согласуется (`2 вещи` / `5 вещей`).

Остальные механики удержания: **счётчик «3/10»** на каждом слайде, **полоса прогресса** сверху
(тёмная дорожка + белая заливка — белым по белому она пропадала на светлых кадрах), **темп
1.5 с/слайд** вместо 2.5 (27 с → ~15 с) и **микро-зум 6%** внутри слайда (`zoompan` с пилой
`mod(on, frames)` — без сброса зум накапливался и второй слайд приезжал уже приближённым).

Безопасная зона: у Reels нижние ~420 px кадра заняты подписью/кнопками/аудио, поэтому весь
вшитый текст держим выше `bottomLimitY()`; прежний футер слайда оказывался в 365 px от низа,
то есть под интерфейсом. В ветке `logo_first` плашка хука рисуется не поверх логотипа, а под
ним (логотип уменьшается и уезжает выше) — иначе смысл ветки терялся.

Обложка Reels — всегда `p{id}-01.jpg` (первое нормализованное фото), фиксированным файлом, а не
«первым элементом списка»: иначе у `logo_first` обложкой становилась карточка логотипа, у
`logo_last` — кадр с хуком, и ветки A/B сравнивали ещё и обложку.

⚠️ **Перегенерация.** Слайды кешируются по имени файла (`p{id}-NN.jpg`), поэтому после правок
рендера мало сбросить статус — надо удалить производные файлы, иначе `generate` переиспользует
старые. Крон `app:social:generate` (*/30) успевает прогнать сотни постов за часы, так что
правки рендера надо доводить до конца ДО того, как очередь разойдётся.

⚠️ **Темп.** Дневной потолок канала = рампа (`rate_start`/`rate_cap` в админке): при
`rate_start=3` это 3 поста/день на весь IG, а 2 бренда/день дают 4 (2 карусели + 2 Reels) плюс
пост обычной сетки. Чтобы очередь не отставала, `rate_start` нужно поднять до ~5 (админка →
Соцсети → Каналы). Отставание не теряет посты: `claimDue` берёт самые старые первыми.

⚠️ **Метрики Reels/каруселей не снимаются**, пока у токена нет скоупа
`instagram_business_manage_insights` (сейчас только `basic` + `content_publish`) — право надо
добавить в Meta-приложении и перевыпустить токен. До этого единственный живой сигнал —
`link_taps` из `app:social:ingest-clicks` (UTM-клики из nginx-логов прода, `utm_content=p<id>`).

**Что реально «в автоматическом режиме»:** plan → generate → qa → scheduled-publish для
карточек/каруселей **и faceless/data-Reels** из данных (рубрики ✅ в §2, медиа-генерация §5).
Founder talking-head и UGC остаются ручными — встают в очередь как `held` с напоминанием.

### 4а. Аккаунт IG: что реально нужно (FB Page больше не требуется)

Распространённое заблуждение «нужна бизнес-страница в Facebook» **устарело**. Актуально (2026):

| Путь | Что нужно | Авто-постинг | Риск |
|---|---|---|---|
| **Official API (реализовано)** | **Professional-аккаунт (Creator достаточно)** — переключение из личного бесплатно, мгновенно, обратимо, без публичных «бизнес»-маркеров. **FB-страница НЕ нужна** — «Instagram API with Instagram Login» (с 07.2024) логинится прямо в IG. Meta-app `wearbase` в **Dev Mode** (App Review не нужен для своего аккаунта), сценарий «Управление сообщениями и контентом в Instagram», права `instagram_business_content_publish` + `instagram_business_basic` | ✅ легально (в рамках ToS), **работает с 2026-07-18** | хард-лимит 25 медиа/24ч; токен ~60 дней, продление кроном (см. ниже) |
| **Личный аккаунт + неофиц. private API** (instagrapi и пр.) | логин по username/password + сохранённая сессия | ⚙️ технически да | 🚫 **против ToS Meta; в 2026 жёсткий энфорсмент** (challenges, 2FA, device-fingerprint) → высокий риск бана/блокировки. Только для тестов/мелочи, **не для основного аккаунта бренда** |
| **«Просто личный аккаунт»** (как делают многие в РФ) | ничего | ❌ только **ручной** постинг с телефона | — |

**Вывод:** «многие в РФ заводят личные аккаунты» — но постят **руками**. Для *автоматической*
публикации достаточно один раз переключить аккаунт в **Creator** (это не «бизнес-страница в FB»,
а бесплатный флажок в настройках IG) → дальше официальный API (Instagram Login) без FB-страницы,
без сторонних сервисов. instagrapi на основном аккаунте — не рекомендуем (бан-риск). Юр-рамка РФ
(§0) — отдельно от технического вопроса аккаунта.

**Картинки:** Meta-краулер не может скачать `image_url` с РФ-прода wearbase.ru (error 9004/2207052)
→ `src/Service/Social/PublicMediaHost.php` конвертит картинку в JPEG и rsync'ит на не-РФ хост
(шведский VPS, systemd-сервис `igmedia` = `python3 -m http.server 80`); Meta качает по обычному
HTTP с голого IP (домен/HTTPS не нужны). Env: `IG_MEDIA_SSH_DEST`, `IG_MEDIA_PUBLIC_BASE`.
Токен — `IG_ACCESS_TOKEN` (сид в `.env.local`, живой токен хранится в `social_channel` id=5,
egress=mac), продление — крон `app:social:refresh-ig-token` (`0 5 * * 1`, Mac). Egress IG — только
с Mac (там поднят VPN, Meta доступна); прод РФ для Meta заблокирован.

## 5. Генерация медиа (image/video): стек, блокеры, маркировка

Подключение генерации апгрейдит часть рубрик из ⚙️/❌ в ✅ (см. §2) — но не «UGC» (это контент
реальных людей, фейк противоречит позиционированию и нарушает маркировку Meta).

**Стек (конкретные сервисы — дёшево/бесплатно, проверено 2026-06):**
| Слой | Рекомендация | Бесплатный fallback / альтернатива | Стоимость |
|---|---|---|---|
| **Публикация TG+VK+IG** | ✅ **РЕАЛИЗОВАНО** — нативные паблишеры без сторонних сервисов: Telegram Bot API, VK `wall.post`, Instagram — официальный **Instagram API with Instagram Login** (`graph.instagram.com`, `InstagramPublisher.php`); Postiz нигде не используется (ни развёрнут, ни в коде) | — | **free** |
| **Картинки** (фоны/сцены) | ✅ **РЕАЛИЗОВАНО** в `MediaRenderer`: цепочка с фолбэком **Gemini → Cloudflare → Pollinations**. По умолчанию **Cloudflare Flux-schnell** (free 10k/день, из РФ, без VPN). Pollinations — фолбэк (free, без ключа). Gemini «Nano Banana» — опц. (качественнее, но image-модель **не бесплатна**: free-квота=0, нужен биллинг ~$0.039/img + Google геоблок РФ → прокси/VPN) | ComfyUI локально только off-peak (см. ниже про железо) | **free** (Cloudflare/Pollinations) |
| **Видео faceless/data** (калькулятор, манифест, статистика) | **Revideo** или **Motion Canvas** (оба MIT, без лицензии) — программный рендер из данных, без AI и без GPU | ⚠️ Remotion мощнее, но BUSL-лицензия ($0 до $1M ARR, дальше платно) — берём MIT-варианты | **free** |
| **Видео product-motion** (image-to-video из реальных фото) | **LTX-2.3** (open weights, fp8 влезает в 16–24GB) на **арендованной** карте; альтернативы — WAN 2.2 5B, MiniMax H3 (медленнее, лицензия с атрибуцией) — см. апдейт ниже | облако по запросу: fal.ai — ByteDance Seedance Fast ~$0.03/сек, Kling 2.5 Turbo ~$0.07/сек | ~$4/день за 5090 / центы за клип |
| **Подписи** | существующая локальная ollama (`LlmService`) | — | **free** |

Итого денежная часть ≈ **0** (всё self-host/free-tier), кроме опционального product-motion видео
в облаке — центы за клип, если не делать локально.

⚠️ **Про LLM-бокс — генерить на нём НЕудобно** (уточнено по факту железа, [[llm-ollama-server]]):
бокс = **3× RTX 2060S (8GB) + 1× A4000 (16GB) = 40GB, CPU всего 2 ядра**. Модель ~26-27B
**слойно размазана по всем картам** (pipeline, активна одна за раз) → **полностью свободной карты
при загруженной модели нет**, а 8GB-карты тесны для Flux. Поэтому:
- **Картинки — лучше через free-cloud** (Cloudflare Workers AI / Pollinations): ноль контеншна,
  ноль новой инфры. Это дефолт.
- **Локально на боксе — только off-peak с выгрузкой модели**: когда очередь брендов пуста →
  `OLLAMA_KEEP_ALIVE=0`/стоп модели (освободить VRAM) → ComfyUI на A4000 (16GB) → вернуть модель.
  Т.е. твой инстинкт «когда очередь освободится» рабочий, но требует выгрузки модели, не просто
  «свободной карты». Грабли [[llm-server-oversubscription]] — ровно про дележ одного ресурса.
- **Видео:** WAN 2.2 14B (40–48GB) на этот бокс **не влезает** (всего 40GB, и те под моделью) →
  **только облако** (fal.ai, центы/клип). Лёгкий LTX на A4000 off-peak — край возможного.

**Апдейт 2026-08-13 — открытые видео-модели (LTX-2.3 / MiniMax H3) и экономика аренды.**
Источник: разбор видео [«Коля Майнер», lqO6UBxCiEo](https://www.youtube.com/watch?v=lqO6UBxCiEo)
(практика на одной RTX 5090) + сверка названий/лицензий по первоисточникам.

- **LTX-2.3** (Lightricks, open weights, ноды `ComfyUI-LTXVideo`) — новый дефолт product-motion:
  fp8-квант заявлен на 16–24 ГБ VRAM. Замеры блогера (5090 32 ГБ, power-limit 400 Вт, шаблонный
  workflow, 8 шагов, без sage-attention): **6с 720p ≈ 48 сек**, апскейл 720p→1080p ≈ 228 сек.
  ⚠️ В сети встречаются и «25–60 мин на 5с клип» — разница в варианте (distilled/fp8 vs полный)
  и числе шагов. Обе цифры — не бенчмарк; свои мерить на арендованной карте.
- **MiniMax H3** (open weights 03.08.2026, ComfyUI day-0; omni-modal, нативное аудио 32 кГц, до
  15с/2K; чекпойнты FL2VA и Ref2VA — это и есть «R2V» из видео): качество выше LTX-2.3, но
  **≈10–15× медленнее** (те же 6с 720p ≈ 11 мин), веса 21–66 ГБ (INT ~34 ГБ) + текст-энкодеры,
  полная модель в 32 ГБ VRAM не лезет.
  🚩 **Лицензия не MIT** — MiniMax H3 Community License: до $20M выручки можно, но обязательна
  видимая атрибуция «MiniMax H3» в продукте, territory-clause исключает US/EU/UK/KR (РФ — нет).
  Для Reels это ещё одна обязательная плашка сверх AI-маркировки (п.3 ниже). У LTX-2.3 таких
  требований нет → для нашего конвейера H3 берём только под конкретную задачу.
- **Тактика:** при 10–15× разнице в скорости выгоднее нагенерить **10 быстрых дублей LTX и выбрать
  лучший**, чем один медленный H3 — ровно наш A/B-паттерн (§4б).
- **Экономика: аренда карты по дням дешевле per-clip API.** Clore: **4090 от $0.50/день**, карты
  вообще от $0.15/день (сверено по кабинету/докам на кадрах, см. референс ниже; «~$4/день за
  5090» — это со слов автора, по факту дешевле). При 48с/клип — сотни клипов за сутки аренды,
  т.е. **центы за десятки клипов**. Против fal.ai Seedance Fast ~$0.03/сек = **~$0.18 за 6с
  клип** — порядок разницы. → **батч** (десятки клипов за сессию) — арендованная карта на день;
  **единичные** клипы — fal.ai (ноль возни с инфрой).
- **Разбор рабочего графа ComfyUI** (промпт-схема `[VISUAL]/[SPEECH]/[SOUNDS]`, имена чекпойнтов,
  сетка мегапиксели→разрешение, замеренная VRAM ~19–20 ГБ на H3-int8, клон голоса CosyVoice3,
  апскейл SeedVR2) — **[`video_gen_comfyui_reference.md`](video_gen_comfyui_reference.md)**.
- **Наш бокс не подходит и по новым цифрам** — упор не в A4000/16 ГБ, а в **7.6 ГБ RAM хоста** и
  **218 ГБ SSD**: веса 21–66 ГБ + энкодеры ~10 ГБ негде держать и нечем подгружать
  (см. [`llm_rig_valuation.md`](llm_rig_valuation.md)). Вывод §5 выше не меняется, только
  подтверждается конкретикой.

**Блокеры «полного авто» (не лечатся генерацией):**
1. **Аудио.** Охват Reels тянет *трендовый* коммерческий звук — его нельзя приклеить через API
   легально. Варианты: лицензионная аудио-библиотека Instagram при ручной публикации (ниже
   автоматизация) либо royalty-free (ниже охват). → финальная сборка Reels со звуком — **semi-auto**.
2. **Логотип/текст в AI-видео** рендерятся с артефактами → бренд-логотип и числа всегда
   оверлеем поверх готового клипа, не доверять генерации.
3. **Маркировка AI-контента (Meta обязательна)** + дисклеймер §0. QA-гейт §4 проверяет наличие
   метки на сгенерированных медиа.

**Правило:** генерация удешевляет производство **реальными брендами** (авто-нарезка, субтитры,
обложки, captions для присланных клипов), а не подменяет живой UGC синтетикой.

## 7. Метрики и closed-loop

KPI этого канала — **не лайки**, а движение по воронке: **saves, shares, profile visits,
link taps** (клики в страницу бренда/калькулятор). Лайки/охват — вторичны.

**Closed-loop (как `app:seo:evaluate-experiments`):** еженедельно `app:social:evaluate` смотрит
per-рубрику saves+shares+link-taps за 14 дней → **масштабирует рубрики-победители** (чаще в
сетке), **режет лузеров**. Винрейт по рубрикам пишется в трекер.

| Метрика | Старт | Цель 3 мес |
|---|---|---|
| Link taps в шапку / нед | 0 | от каждого ✅-поста ≥ baseline |
| Saves на пост (медиана) | — | растёт WoW |
| Профиль→сайт переходы (UTM) | 0 | связать с заходами в каталог/калькулятор |
| Брендов прислали UGC/контент | 0 | 5–10 (питает Reels/UGC рубрики) |

UTM на ссылке в шапке → видеть в аналитике сайта вклад канала (и показывать брендам в ЛК:
«N покупателей из соцсетей» — алиби апгрейда, см. [`marketing_email.md`](marketing_email.md) §3).
