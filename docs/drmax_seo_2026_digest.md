## 1. LLM/GEO-оптимизация и AI Overviews

### AI Overviews ≠ зеркало топ-10
Только 38% ссылок в AI Overviews берутся из органического топ-10 (год назад — 76%); ~31% цитирований — из страниц вне топ-100 (Ahrefs: 60% AIO-цитат вне топ-20). Позиция в поиске и присутствие в AI-ответах — **две разные выдачи**. Стратегия «один ключ → одна лучшая страница» оптимизирует только позиции; для AI единица работы — **тематический кластер**, закрывающий весь спектр под-вопросов. AIO появляются в ~16–21% запросов, чаще по информационным. `[2026-05-26] msg 1489`, `[2026-04-03] msg 1364`

### Query Fan-Out — 5–20 скрытых подзапросов
AI-поиск разбивает один запрос на 8–12 (до 5–20) параллельных подзапросов, каждый получает источники независимо. Страница на позиции 40–70, качественно закрывающая смежный подзапрос, имеет равный с #1 шанс на цитирование.
**Как применить:** разобрать главные страницы на под-вопросы; на каждый — блок прямого ответа (60–100 слов, первое предложение = прямой ответ); под узкие под-вопросы делать отдельные страницы (400–600 слов исчерпывающего ответа > 2000 слов общего); связать всё перекрёстными ссылками (блок «По этой теме», 3–5 ссылок); смоделировать fan-out промптом (декомпозиция запроса на 10+ микрозапросов → из них строить H2/H3). `[2026-05-26] msg 1489`, `[2026-03-05] msg 1298`

### AI Overview Gap Mapping (+ GIST-фильтр)
Метод повышения цитируемости через анализ информационных пробелов.
**Как применить:** 1) снять AIO несколько раз (desktop+mobile, 2–3 формулировки, разные гео) → отделить стабильное ядро от шума; 2) взять cited sources + 2–3 органических конкурента из топ-10; 3) загрузить в LLM пакетом (текст нейроответа + источники + конкуренты); 4) спросить: **какие критичные факты, цифры, ограничения есть у конкурентов, но игнорированы в AIO?**; 5) искать числа вместо прилагательных, условия/ограничения, пограничные сценарии, компактные сравнения; 6) вставить найденное в верхнюю треть страницы (прямой ответ, числа/даты, источник, 3–6 предложений или таблица, дата обновления).
**GIST-фильтр** для каждого gap: усиливает интент или размывает? делает страницу незаменимой? можно ли оформить коротким извлекаемым блоком? → внедрить в текущий URL / вынести в дочерний / выбросить.
Не поможет вне топ-10 и без собственной фактуры. `[2026-06-15] msg 1538`, `[2026-06-16] msg 1540`

### Оптимизация под цитируемость (cite-safety, extractable blocks)
Answer-engines извлекают контент модульно. Абзац, теряющий смысл вне контекста, исключается из генеративной выдачи.
**Самодостаточный блок = утверждение + краткое объяснение + граница применимости + пример/источник.** Тест «вырежи секцию»: скопируй блок с подзаголовком в пустой документ — если непонятен без контекста, он не годится для цитирования.
**Как применить:** первый абзац = прямой ответ (не вступление); подзаголовки = микро-вопросы, не темы; 2–4 «цитируемых блока» (40–80 слов) на странице (определение / способ действия / сравнение / ограничение); после таблицы/списка — одно предложение-вывод обычным текстом; добавлять происхождение факта в текст (кто автор, на чём основан вывод, откуда данные, когда обновлены). Объём блоков — 2–5 тыс. символов, не «портянки». `[2026-02-17] msg 1267`, `[2026-04-03] msg 1364`

### Первые 150–200 слов = машинный интерфейс страницы
Первые 150–200 слов — семантическое первичное согласование документа с LLM (идентификация сущности, интента, доверия).
**Что должно быть:** источник (бренд/автор как сущность), область знания (домен применимости), формат (гайд/кейс/чек-лист/сравнение), границы применимости. Плюс одно **Extractable Statement** — самодостаточное предложение (1–2 сущности + 1 причинно-следственная связь + измеримый эффект), которое часто становится ядром AIO.
Три промпта: **AI First-200 Optimizer** (переписать блок ≤200 слов), **LLM-as-a-Classifier** (проверить, отвечает ли блок на 4 вопроса: кто источник / о чём / для кого / в каком формате), **AI Citation Booster** (найти/создать цитируемое предложение). `[2026-01-13] msg 1189–1190`

### LLM Memory Anchors (якоря памяти)
Лаконичные контрастные фразы (≤15 слов), которые LLM захватывает как «базовую истину».
**Как применить:** генерировать 10 фраз (антитезность, однозначность, плотность смысла, ритм); 2–3 якоря в начало (above the fold) списком, оборачивать в `<blockquote>`/`<strong>`; переиспользовать как посты в соцсети. Пример: «В 2026 техническое SEO стало минимумом, а поведенческие факторы и экспертность авторов — главный драйвер роста». `[2026-03-05] msg 1299`

### Управление синтезом ИИ через первичные данные («инференс»)
Не управлять AI-ответом напрямую, а управлять качеством **входных данных**: публикуешь верифицированные первичные факты → AI синтезирует.
**Как применить:** публиковать структурированный фактический материал (продукт, методология, экспертиза, история); после индексации задавать AI ключевые вопросы; видеть пробелы (где отвечает конкурент, где галлюцинация, где тишина); закрывать узлы. Диагностика галлюцинации: если AI приписал вам небывшее — опубликовать точное опровержение с фактами (исчезает за 3–4 недели). Связь с GIST: узкоспециализированный первичный контент бьёт авторитет крупных сайтов. `[2026-06-03] msg 1515`

## 2. Как боты и LLM читают страницу (HTML-семантика, чанкинг, лимиты)

### Бюджеты чтения — 2 МБ и токены
Googlebot читает только первые **2 МБ HTML** (с февраля 2026). У LLM фиксированный бюджет контекста (~5700 символов у ChatGPT Deep Research). Сырой HTML = 50–200k токенов, реальный контент = 500–2000; **96% токенов — шум** (скрипты, навигация, футер, реклама, CSS).
**Как применить:** прямой ответ — в первый абзац после H1; урезать header на SEO-страницах, mega-menu (тысячи ссылок) вынести в конец `<body>` в отдельный `<nav aria-label>`; второстепенные блоки — ниже `<article>`; чистить inline CSS/JS из тела; семантика `<main>`/`<article>` для сути, `<nav>`, `<aside>` для хлама; **проверять сырой HTML, а не рендер** (размер документа, порядок блоков, объём кода до текста). `[2026-06-30] msg 1580`

### Чанкинг критичен (Google врёт, что не нужен)
Внутри Google — MUVERA (multi-vector retrieval), passage-level индексация с 2021 (пассажи ранжируются независимо). Тест на Gemini API: разбивка абзаца на два тематически чистых фрагмента → +15% и +10% retrieval score.
**Как применить:** «одна идея — один абзац» (утверждение + обоснование); ключевые факты (цены, характеристики, выводы, определения) — чистым текстом в первой трети, **не в JS-компонентах**; атрибутируемые утверждения с провенансом («По данным Google (2024), снижение LCP с 4s до 2.5s даёт +12% конверсий»); каждый H2/H3 самодостаточен как «якорь retrieval». `[2026-05-25] msg 1487`

### SemanticRank Orchestrator — аудит семантической вёрстки
Система (6 .md + 48 команд) ищет gaps: факты текстом вместо `dl/dt/dd`; сравнение на div-grid вместо `<table>`; несколько сущностей в одном контейнере без границ; отзывы/кейсы/вакансии не как отдельные `<article>`; условия/ограничения в длинном тексте без `<section>`; даты без `<time datetime>`; важные факты только визуально без текстового дубля; шаблонный шум конкурирует с primary content в DOM. 3 режима (Quick / Full / Production Report со scoring по 5 осям). `[2026-06-18] msg 1546`

### Заголовки как якоря интерпретации
h1 — основной идентификатор темы (сущность + контекст + интент: «Ремонт ванной комнаты в квартире: этапы, сроки и стоимость», не «Всё о ремонте»). h2–h4 — логическая карта (каждый h2 — подтема h1, без тематических скачков). LLM цитируют самодостаточные h2/h3 напрямую. title (шире, маркетинговее, синонимы — для SERP) ≠ h1 (точнее, сущностнее — для интерпретации). `[2026-01-18] msg 1204`

### alt/title как скрытый семантический слой
Google не верит alt по умолчанию — сверяет пиксели с контекстом (несоответствие = негативный сигнал). Формула alt: `[что изображено] + [в каком контексте] + [почему важно для темы]`. Все alt на странице должны быть связаны по теме (LLM читает их как кластер). title — слабый уточняющий сигнал, особенно для ссылок. `[2026-01-16] msg 1201`

## 3. Контент-стратегия под AI

### Коммодитизация и Information Gain
LLM оценивает не наличие цифры, а прирост знания относительно уже виденного. `contentEffort` — алгоритмическая оценка «невоспроизводимости» (текст за 30 сек → к нулю).
**4 способа создать information gain:** 1) цифры только как именованное сравнение с методологией («использует 2.3M команд, что делает наиболее проверенным»); 2) другой угол («Почему 95% линкбилдинг-бюджета профукивается» вместо «10 лучших инструментов»); 3) причинность вместо описания; 4) другая последовательность подачи (результат → как получили → что не сработало, а не проблема → решение → пример).
**Структура:** главный вывод/цифра в первый экран → что измерено и на какой выборке → блок методологии → конкретные варианты по имени. Три вектора новизны: entities, data, perspective. Правило: «переписывание ради объёма запрещено; только изменения, снижающие overlap с SERP или дающие one-step information gain». Собирать first-party: отзывы, sales calls, support tickets, реальные цены, возражения; вести delete-list (что вырезать без замены). `[2026-07-09] msg 1599`, `[2026-03-25] msg 1346`

### Фреймворк контрастной семантики (Negative Definitions)
LLM учатся на контрастах — легче понять объект, если сказать, чем он **НЕ** является. Заявлено +70% к вероятности цитирования.
**Правила:** точность («не является классической CRM», не «не имеет аналогов»); отрицать только то, с чем реально путают; одно отрицание = один факт. **3 схемы:** прямое отсечение («GEO — это НЕ классическое SEO. В отличие от SEO, GEO не опирается на плотность ключей…»), маркированный список, контрастная таблица (Атрибут | Наше | НЕ является). Триггеры: «В отличие от…», «Не следует путать с…», «Ключевое отличие от…».
**Практика:** топ-20 страниц, теряющих показы в AIO → добавить блок «Что это, а чем НЕ является» в первый экран → переиндекс → замер через 14 дней. `[2026-07-04] msg 1590`

### Свежесть — «срок годности» ~90 дней
Контент без обновления 90 дней выпадает из AI-ответов; 50% цитируемого младше 13 недель; AI-цитируемый контент на 25,7% свежее органического. Google различает 4 состояния: недавно обновлён (буст) / корректно статичен (нейтрально) / искусственно освежён датой (штраф) / устарел (выпадение). Кейс David Baum: 60-дневный цикл обновления топ-20 (~1 ч/материал/квартал) → 7 из 20 вошли в AI-цитирование после первого обновления.
**Как применить:** реестр цитируемых материалов; поле «дата обновления» видимым тегом в HTML; 60-дневный триггер обновления (не переписывание): +1 свежая статистика с источником, +1 пример, блок «Обновлено [мес. год]: что актуально», новая цитата эксперта; проверять видимость краулеру (Firecrawl / Jina Reader). **Не** менять структуру и не публиковать заново. `[2026-05-29] msg 1504`

### Смещение оптимизации на процесс + «невидимые» данные + анти-обобщающие якоря
ИИ хорошо генерирует результаты, плохо — процессы. Добавлять layer process narrative («Как мы к этому пришли»: гипотезы, ограничения, что не сработало и почему) — сигнал Experience. Встраивать «невидимые» данные: точные пороги («при нагрузке выше 70%»), временные лаги («эффект через 12 дней»), количественные ограничения («работает при 3–5 итерациях»). Анти-обобщающие якоря: «работает только если…», «в нашем случае не сработало, потому что…», «неприменимо при…». `[2026-01-10] msg 1186`

### Entity-Based SEO, семантическая полнота, entity-gap
Страница ранжируется, когда её фрагменты/заголовок/центральный объект/связанные сущности складываются в одну тему (без topic drift). **Entity-Gap Analyzer:** инвентаризация сущностей (объекты, процессы, характеристики, E-E-A-T-подтверждения) → выявление устаревших и пропущенных (LSI/entity gaps) → вердикт по покрытию.
**Слоистое наращивание:** если у страницы есть трафик/позиции — **не переписывать**, доращивать слоями (каждый недостающий кластер сущностей = новый абзац, встроенный в структуру); нет трафика — переделывать целиком. Взять лучшие статьи 2023–2024 и добавить 1–2 слоя данными 2026 (сигнал freshness). Затем Entity QA: актуальность пруфов, соответствие мета-тегов, связность. `[2026-03-20] msg 1335`, `[2026-01-24] msg 1210`, `[2026-01-28] msg 1222`, `[2026-01-29] msg 1224`

### Перенасыщение: больше страниц ≠ больше трафика
Модель «больше страниц = рост» умерла (внутренняя конкуренция, распыление авторитета, перерасход обхода). Reddit Mapper вместо семантического дерева ищет: неразрешённые решения, точки разочарования (возврат в поиск), ошибочные ожидания, редкие сценарии («когда не подходит»), собственные наблюдения/данные. **Дерево решений пользователя:** до выбора (чего боится, что сравнивает) / во время (по каким признакам отсеивает) / после опыта (что разочаровывает) / после неудачи (почему не устроил). `[2026-04-30] msg 1432`

### Featured Snippets — скрытый S-V-O + тип интента
Чистый S-V-O не берёт сниппет; работает «скрытый» (завершённая инструкция с внутренним скелетом «вы моете раму тёплой водой»). Схема зависит от интента: Definitional → S-V-O (1–2 declarative); Procedural → A-M-O (imperative/список); Comparison → X-vs-Y; Cause-Effect → C→E. Приоритет смешанных: Fact/Numeric > Definitional > Eligibility > Procedural > Cause-Effect > Repair > Comparison > Recommendation > Exploratory. Анализировать в Gemini (Google Search базируется на нём). `[2026-02-06] msg 1243–1246`

## 4. Entity / бренд (граф знаний, entity poisoning)

### Как Google собирает сущность бренда
Граф строится из сайта, отзывов, LinkedIn, GBP, вакансий, карт. В 2025 Google удалил **3 млрд сущностей за неделю** (77% event, 15% thing) → нужна ясная сущность, не мусор. Иерархия: Brand → Services → Audiences → Proof → Geography → Reputation.
**Как применить:** свести бренд к одному primary statement (совпадает на Home / About / LinkedIn / GBP); убрать шаблоны («quality service»); связать услугу с аудиторией («technical SEO audits for multilingual ecommerce», не «SEO audits»); критичные атрибуты — из картинок/слайдеров/табов в индексируемый текст; собрать proof-слой (кейсы, локации, эксперты, партнёры); проверить, не спорят ли отзывы с позиционированием. Инструмент: Entity Footprint промпт. `[2026-06-23] msg 1564`

### Entity Poisoning — защита бренда в LLM
Конкуренты встраивают ложь через UGC → падает Confidence Score → негативные AI-ответы. Уязвимости RAG: Semantic Data Poisoning (массовая публикация меняющих ассоциации текстов), Entity Split & Collision, Narrative Richness Bias (ИИ ценит «богатство нарратива» выше авторитета домена → детальные выдумки на UGC работают), Fine-Tuning Vulnerability (<100 примеров ломают объективность), Embedding Filters Blindness.
**Защита:** жёстко фиксировать сущность (кто вы, официальный домен, канонические факты); Data Provenance Lock (Schema `@id` ↔ Wikidata); форензик-разбор («какие формулировки о бренде LLM сочтёт правдоподобными?»). Инструмент: Brand Entity Poisoning Forensics. `[2026-07-02] msg 1585–1586`

### Search Profiles для авторов
Отдельные Google-страницы для авторов с аудиторией (порог 100k YouTube/IG/X или 300k TikTok). Прямого буста ранжирования нет, но данные попадают в панель знаний — сигнал E-E-A-T. Синхронизировать имя/фото/описание/ссылки на сайте, соцсетях, авторских страницах; усиливать брендовый поиск по имени; стягивать сайт+YouTube+соцсети к одной сущности. `[2026-06-05] msg 1528`

## 5. Google Search Console

### Regex-фильтры под AI Overviews + Trigger Rate
Найти запросы, вероятно вызывающие AIO (~21% baseline). Выгрузить CSV → подать в LLM → сгруппировать по формату контента.
**Мастер-regex (RU):** `(?i)^(что такое|что это|как|как сделать|как выбрать|почему|когда|где|кто|какой|лучший|топ|vs|сравн|разница между|обзор|альтернатив|руководств|гайд|чеклист|список|примеры|польза|преимущества|недостатки|цена|как исправить|для начинающих)`
**8 модульных фильтров с trigger rate (EN):** Вопросы (what/how/why…) — **57,9%** (втрое выше baseline; 66,5% всех AIO — вопросы); Сравнения (vs/difference) — **26,2%** (100% RAG в LLM); How-to/Process — **~58%** (максимальный zero-click риск: CTR #1 падает на 34,5–61% при AIO); Freshness (latest/current/год) — **100% RAG** (единственная экспериментально подтверждённая); + Best/Top, Определения, Commercial, Conversational (9+ слов). `[2026-07-13] msg 1612`, `[2026-07-13] msg 1614`

### Архитектура «прямой ответ» по группам запросов
Общий принцип: H2/H3 = вопрос из запроса → инкапсулированный ответ 40–60 слов (самодостаточный) → развёрнутый материал.
- **Вопросительные:** H2 = дословно запрос; параграф 1 (40–60 сл.) = `[Термин] — это [определение]. [Механизм]. [Значение].`
- **Сравнения:** H1 «X или Y: что выбрать для [задача] в 2026?»; вердикт 40–60 сл.; таблица 8–12 строк; «Когда выбрать X / Y» + экспертный комментарий (+28% шанс); Schema Review+AggregateRating.
- **Best/Top:** H2 «#N. [Название]: лучший для [сценарий]»; сводная таблица вверху; методология отбора (E-E-A-T); Schema ItemList+dateModified.
- **Определения:** H1 «Что такое [Термин]: определение, принцип, зачем»; первые 20 слов — полное имя+аббревиатура+область; Schema DefinedTerm/Article.
- **How-to:** вводный параграф (шаги, время, что понадобится); H2 = действие+объект («Шаг 1: Настройте X»); нумерованный список; Schema HowTo+HowToStep.

Простейший метод: запрос в `<h2>` + ответ 40–60 слов под ним. `[2026-07-14] msg 1617`

### GSC-данные были завышены (май 2025 – апр 2026)
Google признал ошибку логирования, завышавшую показы 11 месяцев (параметр `&num=100`: боты грузили 100 результатов, каждый = 100 показов; отключён сент. 2025). Сравнения год-к-году с попаданием в это окно требуют пересчёта. **Первичный KPI — клики, не показы.** `[2026-05-14] msg 1464`

### Мониторинг перехвата трафика через BigQuery
Экспорт GSC → BigQuery; SQL по лонг-тейлу: искать низкочастотные кластеры со стабильной позицией, но упавшим CTR = признак, что AIO перехватил трафик → направлять туда новые внешние публикации. `[2026-07-01] msg 1583`

## 6. Техническое SEO и алгоритмы Google

### Пайплайн ранжирования (суд US vs Google + утечка Content Warehouse)
Alexandria (индекс) → SegIndexer → Mustang (скоринг) → NavBoost (поведенческая валидация) → Twiddlers (корректировки); RAG — обёртка поверх. Ключевые атрибуты: `scaledSelectionTierRank` (уровень тиринга; landfill почти не участвует в AI-генерации), `isRoboted`/`isCrawled` (проверять до любой AI-оптимизации), `contentEffort`, `ContentChecksum96` (дубли по содержимому, не URL), `clutterScore` (агрессивная реклама в одной части портит весь домен), `OriginalContentScore`, `original_media_score` (оригинальные картинки > стоковых).
**Как применить:** аудит `scaledSelectionTierRank`; anti-replicability (структуры, которые LLM не воспроизведёт — хронологии, нестандартные сравнения); смещать уникальность из текста в данные; явные человеческие ограничения (цифры, даты, неудачи); закрытые экспертные кластеры. `[2026-05-15] msg 1466`

### GIST (Greedy Independent Set Thresholding) и «потолок 56%»
Google отбирает подмножество источников: максимум пользы при минимуме избыточности. VIP-узел (Wikipedia, офсайт) получает высший Utility Score, вокруг него Conflict Radius по семантической близости — всё внутри исключается. Математический предел полезности+разнообразия — **55,84%** (NP-трудно); ваша 99%-достоверная страница = «балласт», если повторяет лидера. GIST гарантирует ≥50% (до 55,8%).
**Как применить:** сжать общеизвестное в начало, объём — на редкие данные/исключения/спорное/свои наблюдения; собрать карту 10 тезисов конкурентов и НЕ использовать их, найти 3–5 недостающих узлов; раздел «кому подходит / не подходит / когда не сработает»; разводить близкие страницы по интентам, не по ключам; использовать другой класс источников (справки, changelog, патенты, обсуждения, свои тесты); выносить общую теорию в опорную страницу, на дочерних — только что меняется. `[2026-05-04] msg 1444`, `[2026-05-05] msg 1445`, `[2026-07-09] msg 1600`

### Агентный RAG в AI-поиске (5 узлов)
Схема «запрос → топ-N → ответ» мертва. Пайплайн: планировщик → маршрутизатор → поиск → попарное ранжирование → критик (требует достаточно доказательств, отсеивает однобокость). **Как применить:** топическая плотность (5–20 подзапросов → узлы кластера); атомарные абзацы (именованные сущности в начале, явные условия применимости, таблицы/числа); раздел «когда не работает»; «мостовые сущности» (связь темы A с B → цитирование там, где ваш сайт не упоминался); для вычислимых задач маршрутизатор выберет API/калькулятор, не статью; свежесть как фильтр критика. Локальный тест: `agentic-rag-audit` (iPullRank, GitHub `ipullrank/agentic-rag-distillation`, Ollama+gemma4:e2b, SerpAPI) — «Brand Journey» показывает, какие подзапросы нашли URL и что сказал критик. `[2026-05-31] msg 1508–1510`

### Валидность HTML — не фактор ранжирования
Гари Иллиес: невалидность сама по себе не штрафуется; штрафуют последствия (сломанная перелинковка из-за битого `<a>`). Вывод: большинство «факторов ранжирования» — сигналы штрафов; к бусту ведёт мало что (в первую очередь внешние ссылки). `[2026-03-02] msg 1291`

### Sandbox — миф
«Sandbox» как массовый фильтр для новых сайтов — миф. Есть подавление свежего спама, но дело не в возрасте, а в том, похож ли сайт на спам или на легитимный бренд. `[2026-03-19] msg 1333`

### Disavow по целому TLD
Недокументированная фича Disavow: `domain:abc` (где abc — TLD, напр. `.info`) прихлопывает спамерские ссылки с целого TLD превентивно. Осторожно. `[2026-03-10] msg 1307`

## 10. Линкбилдинг и off-page

### Off-page как страховка от галлюцинаций LLM

## 11. International SEO

### Семантический коллапс и Market-Scoped Differentiation
LLM понимают смысл, не язык: EN «How to optimize taxes» и ES «Cómo optimizar impuestos» имеют почти идентичные векторы → ИИ дедуплицирует по Cosine Similarity, оставляя старший по трасту (обычно EN). **hreflang не спасает** (это директива для Googlebot, LLM опираются на смысл).
**Решение — MSD (3 уровня):** 1) локальные сущности («для Испании — Bizum и BBVA», не «популярные платёжки») → новые узлы графа = уникальный источник для рынка; 2) юридическая специфика (GDPR/LOPDGDD — сильнейшие локальные сигналы); 3) экономическая адаптация (не переводить кейсы, а заменять локальными отзывами; локальный прайсинг). Плюс Schema Audience `geographicArea` + offers `eligibleRegion`; разделение авторов по рынкам с локальными LinkedIn. `[2026-07-03] msg 1588`

### Bing Webmaster Tools — GEO-инструменты
Первый полезный интерфейс для GEO/AI SEO: **Citation Share** (% ваших цитирований по grounding query), **Intents** (14 типов), **Topics** (тематические кластеры), **Compare** (динамика). Workflow: экспорт Pages+Citation Share → обогатить данными GSC/CRM (параметр Value) → сегментировать по интенту → приоритет **High Value / Weak Share** (ценно бизнесу, но ИИ игнорирует) → доработка (сущности, первичные данные, форматирование) → переобход → валидация через 2–4 недели. ⚠️ Citation Share — наблюдательная метрика, не KPI. `[2026-06-21] msg 1551`, `[2026-04-28] msg 1425`

## Применение в WEARBASE (приоритеты)

Каталог российских брендов, RAG-генерация контента, noindex не-ru локалей, семейный гардероб — с поправкой на это:

1. **Карточки брендов/товаров под цитируемость (высокий приоритет).** Первый абзац = прямой ответ; факты (город, год основания, категории, цены) чистым текстом в первой трети, не в JS; блоки 40–80 слов; `contentEffort`/information gain — добавлять first-party (наши атрибуты, ниша-специфику), а не рерайт. Прогнать `SemanticRank`-логику по `tailwind/brand/show.html.twig`: сущности в границах `<section>`/`<article>`, даты через `<time datetime>`.
2. **RAG-генерация (встроить в промпты `BrandRagService`/`GenerateBrandContentCommand`).** Правило «negative definitions» (чем бренд НЕ является — не путать с масс-маркетом/иностранным аналогом), извлекаемые блоки, GIST-принцип (не повторять 10 общих тезисов, давать 3–5 уникальных узлов). DrMax-знания теперь в `topic_chunks`/role=seo — можно подмешивать в генерацию через `AdvisorRag::retrieve($q, ['seo'])`.
3. **GSC regex-фильтры (быстрая победа).** Прогнать RU-мастер-regex по нашему GSC-экспорту → найти запросы с высоким trigger rate (вопросы ~58%, freshness 100%) → под них делать H2=вопрос + ответ 40–60 слов на страницах брендов/категорий/блога.
4. **Свежесть (60–90-дневный цикл).** Реестр топ-цитируемых страниц + видимая «дата обновления»; для блога — обновлять, а не только плодить новые slug (согласуется с политикой «не перезаписывать готовые статьи новым slug»).
5. **Entity/бренд-граф.** Один primary statement WEARBASE на Home/About/соцсетях; авторская сущность (Анна Семянникова) — `sameAs`, привязка к графу; entity-poisoning-мониторинг для крупных брендов каталога.
6. **International (когда появятся реальные переводы).** Текущий noindex не-ru локалей корректен именно из-за семантического коллапса — русский fallback схлопнется в векторах. Открывать локаль стоит только с MSD (локальные сущности/юридика/кейсы под рынок), а не переводом.
7. **Off-page / подборки.** Входить в чужие подборки «российские бренды одежды» (редакционные пробелы), а не саморекламные; упоминания бренда WEARBASE в UGC важнее анкоров для AI-видимости.
8. **Мониторинг перехвата (BigQuery).** Отслеживать кластеры со стабильной позицией и упавшим CTR = AIO перехватил; интегрировать в дайджест-отчётность.
