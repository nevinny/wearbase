# Роадмап фичи «цифровой гардероб» по разбору конкурентов, 2026-09-23

Источники разной степени доверия — важно не смешивать:

- **Verified (прямой скрейп официальных сайтов, эта сессия)** — `docs/wardrobe-competitors-facts_2026-09-23.md`: Fits, GetWardrobe, N2B.
- **Secondary (пересказ Т—Ж, не проверено напрямую)** — Acloset.
- **Crawled (обход блога через `app:seo:competitor-site-crawl`, PR #250)** — 13 постов блога Fits: разбор шкафа, AI-стилист/рейтинг образов, топ-листинги приложений.
- **Unverified (файл `digital_wardrobe_apps_analysis.html`, принесён пользователем)** — похож на LLM-сгенерированный отчёт. Содержит минимум 2 проверенные ошибки (N2B помечен «бесплатный» — по факту 5-дневный триал на 10 вещей; Fits помечен «нет ИИ-удаления фона» — по факту есть безлимитно на free). Идеи оттуда берём только как гипотезы для проверки, не как факты.

## Что у WEARBASE уже есть (актуальный baseline)

Фото/ссылка → AI-черновик (категория, цвет; бренд — вручную; состав — только по читаемой бирке) → подтверждение человеком → статусы вещи («носится»/«на вырост»/«мала»/«отдана», в т.ч. передача между детьми) → AI-стилист (до 3 образов из «носится», с обратной связью, **с 2026-09 учитывает погоду** — condition+температура, сейчас только Москва, fail-soft) → журнал носки (счётчик надеваний). Плюс `price`, `purchasedAt`, `purchaseReason`, `pros`/`cons`/`verdict`, `loveAtFirstSight` уже есть как поля вещи (см. `WardrobeItem`) — используются пока не для всех этих есть UI/фичи поверх, судя по фактам генераторов контента.

## Приоритет 1 — почти бесплатно технически, прямое попадание в тренд

**Cost-per-wear (стоимость одной носки) как отображаемая метрика.**
У `WardrobeItem` уже есть поле `price`, журнал носки уже считает количество
надеваний — не хватает только вычисляемого отображения `price / кол-во носок`
в карточке вещи. Это ровно тот тренд, который отметили и наш собственный
сгенерированный контент («метод стоимости одного использования»), и внешний
файл-отчёт (CPW-экономика), и GetWardrobe (verified: у них это отдельная
платная фича — «глубокий анализ расходов»). У нас есть шанс сделать это
**бесплатно** там, где у GetWardrobe это часть Premium — реальный
дифференциатор, не косметика.
**Действие:** проверить, есть ли уже расчёт CPW в UI карточки вещи; если нет —
небольшая фича (вычисление на лету, без миграций).

## Приоритет 2 — реальный разрыв с несколькими конкурентами, требует продуктового решения

**Список для сборов в поездку (packing list) как фича, не просто совет.**
Verified: GetWardrobe (Premium) имеет «списки для сборов в поездку». Наша
статья «Гардероб в поездке» (PR #250) честно НЕ утверждает наличие такой
фичи — описывает только ручной просмотр фото по статусам. Разрыв между
контентом (обещаем удобство сборов) и продуктом (нет спец-инструмента) можно
закрыть: простой список «выбрал N вещей из гардероба → получил чемодан-лист»
поверх уже существующих данных (статусы, категории, сезон уже есть как поля).

**Нативные приложения / доступ без установки на экран.**
Verified: у GetWardrobe (iOS/Android/macOS/веб с синком), Fits (iOS/Android,
1M+ юзеров), N2B (iOS/Android) — везде нативный клиент. WEARBASE сейчас —
PWA (добавление на экран через Safari «Поделиться», см. лендинг). Это
крупный разрыв, но и крупная инвестиция — не «быстрая победа», отдельное
стратегическое решение, не пункт для этого роадмапа как таковой, просто
фиксирую как известный разрыв.

## Приоритет 3 — стоит проверить спрос перед тем, как строить

**Ресейл-интеграция («вещь не носилась 6+ месяцев → предложить продать»).**
Источник — ТОЛЬКО unverified-файл (упоминает связку с Oskelly). Не подтверждено
ни у одного verified-конкурента напрямую. Но логически стыкуется с уже
существующим журналом носки (можно детектить «мёртвый груз» автоматически,
без новых данных) и с философией «покупайте реже» с лендинга. **Перед тем как
строить — проверить, есть ли у WEARBASE вообще ресейл/маркетплейс-функционал
или партнёрство, куда это могло бы вести** (не проверял в рамках этой сессии).

**Виртуальная примерка (virtual try-on).**
Источник — Fits Pro (verified: «30 AI credits/month для... виртуальной
примерки») + unverified-файл упоминает то же для Outfitly. Технически
сложная фича (нужна модель позы/тела), высокая стоимость разработки. Не
делать без отдельной проверки спроса — не тянуть только потому что у
конкурента есть.

## Не берём в роадмап (сознательно)

- **Соц-функции (гардеробы друзей, сообщество)** — есть у Fits (verified), но
  плохо стыкуется с приватной/семейной позиционированием WEARBASE (см. лендинг:
  «Семейные данные не становятся публичными»). Противоречит текущему UX-принципу,
  не тянуть бездумно.
- **Маркетплейс стилистов** (N2B, verified) — у WEARBASE уже есть похожий,
  но другой по форме путь — платный concierge (человек оцифровывает вещи
  выездом). Расширение до полноценного маркетплейса стилистов — это другой
  продукт, не инкремент, требует отдельного решения, не просто «у конкурента
  есть — добавим».
- **Любые пункты только из unverified-файла без независимого подтверждения**
  (completeness-индексы, конкретные цифры функциональности) — файл уже поймали
  на 2 фактических ошибках, доверять его конкретике нельзя без перепроверки.
