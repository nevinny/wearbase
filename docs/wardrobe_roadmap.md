# «Мой гардероб» → семейная гардеробная система: видение и роадмап

Дата: 2026-07-11. Источник: владелец продукта (запрос супруги как первого пользователя →
стратегическая продуктовая ставка).

## Ключевая идея

**Гардероб для всей семьи** — key differentiator: у существующих гардеробных аналогов
(Whering, Indyx, Acloset и пр.) семейного контура нет, они все про личный шкаф одного
человека. Семья из 5+ детей — идеальный сценарий: вещи живут дольше одного носителя.

Синергия с WEARBASE-каталогом: вещи → ссылки на бренды каталога, вишлисты → трафик
брендам, AI-стилист → работает на данных RAG-конвейера брендов.

## Итерации

| # | Что | Статус |
|---|---|---|
| 1 | Веб-CRUD `/account/wardrobe`: карточки, фото, статистика, импорт | ✅ 2026-07-11 |
| 2 | TG-ввод через @wearbase_bot (шаблон+фото → карточка+статистика) | ✅ 2026-07-11 |
| 3 | **Семья**: дети = отдельные аккаунты (без email, claim позже), права родителя, передача вещей старшие→младшие с историей, статусы (носится/на вырост/мала/отдана), TG: «Кому:» + передача | 🔨 в дизайне |
| 4 | **Совместные покупки**: вишлисты, одобрение покупки родителем (ребёнок просит → родитель подтверждает), бюджетирование (на ребёнка / семью / период) | план |
| 5 | **AI-стилист** (локальный LLM-стек: ollama gemma4 + embeddings): составление капсул из имеющегося; «hardlink» сочетаемости вещь↔вещь (что с чем носить); подбор образа на выход (событие/погода → комплект из гардероба) | план |
| 6 | Mobile-first приложение (Flutter) | план |

## Extension points, заложенные в фундамент итерации 3

- `Family` — первоклассная сущность (к ней цепляются бюджеты и вишлисты итерации 4).
- `wear_status` — расширяемое строковое поле (вишлист/awaiting_approval — кандидаты
  на отдельную сущность, решается в итерации 4).
- `WardrobeItem` готов к AI-атрибутам (цвет/сезон/стиль) и связям item↔item (итерация 5) —
  отдельными таблицами, схему менять не потребуется.
- `source` уже есть (web|telegram|import) — добавится mobile.

## Технические заметки

- AI-фичи (ит. 5) гонять на существующем LLM-сервере (gemma4:26b + qwen3-embedding):
  сочетаемость = эмбеддинги атрибутов вещей + LLM-судья; капсулы/образы = генерация
  по структурированному гардеробу. Отдельный внешний API не нужен.
- Бюджетирование (ит. 4): цены уже в RUB (конвенция проекта), статистика трат по
  носителю есть с итерации 1; исходный покупатель фиксируется историей передач (ит. 3).
- Детские аккаунты без email — см. дизайн итерации 3 (механика claim при взрослении).
