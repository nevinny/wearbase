# ТЗ: Аренда магазина брендам (multi-tenant SaaS, white-label витрина)

**Модель (решения владельца):** полный магазин (каталог+корзина+оплата+ЛК); **фикс-подписка** (entity `Subscription` уже есть); **SaaS + свой домен — сначала**, self-hosted — потом; витрина **настраиваемая** — даём готовый шаблон, кастомизация как **платная доп-опция**.

**Суть одной строкой:** «отвязать витрину бренда от каталога wearbase в самостоятельный магазин на своём домене, на нашем движке, по подписке».

---

## 1. Позиционирование vs Tilda/Shopify/Insales (важно — это их территория)

Лобовая конкуренция с конструкторами сайтов проигрышна (у них огромный функционал). **Наш wedge — вертикаль + сеть + готовые РФ-узлы, а не «ещё один конструктор»:**

1. **Вертикаль:** заточено под РФ-бренды одежды (не универсальный конструктор) — нужные поля, категории, размерные сетки, шаблоны fashion из коробки.
2. **Сеть/трафик:** у бренда УЖЕ есть страница в каталоге wearbase → аренда магазина + catalog-discovery = приток покупателей из каталога. Tilda трафик не даёт — у нас network effect.
3. **AI-контент из коробки:** RAG-генерация описаний/SEO/FAQ (уже построено) — у Tilda этого нет.
4. **РФ-платежи и юр-слой решены:** YooKassa, `SellerLegalEntity`/оферты/возврат предоплаты (ЗоЗПП) — то, что у бренда болит, у нас готово.
5. **Деньги напрямую бренду** (без комиссии с продаж) + фикс-подписка за инфраструктуру — честнее маркетплейса.

Формула: **«Tilda для РФ-фэшн-брендов со встроенным трафиком каталога, AI-контентом и РФ-комплаенсом»**, а не generic store-builder.

---

## 2. Что УЖЕ переиспользуем из wearbase (готово — экономит 70% работы)

- ЛК бренда (`BrandLk/*` контроллеры), управление товарами/медиа/командой.
- Товары, заказы (`Product`, `Order`), корзина, чекаут.
- Платежи: `PaymentService`, `PaymentGatewayRegistry`, YooKassa, `SellerLegalEntity`/`SellerPaymentAccount`/оферты.
- **Подписки: `Subscription`** — основа биллинга аренды.
- RAG-контент (описания/SEO/FAQ), переводы (i18n), мультивалюта.
- Tailwind-витрина бренда (`templates/tailwind/brand/`) — основа арендного шаблона.

**По сути арендный магазин = существующий «бренд» wearbase, но: (а) на своём домене, (б) корень `/` = его витрина (не каталог), (в) включён по активной подписке.**

---

## 3. Что нужно ПОСТРОИТЬ (ядро новой работы — мультитенантность)

### 3.1 Резолв тенанта по домену
- Таблица `tenant_domain` (`brand_id`, `domain`, `is_primary`, `verified_at`, `ssl_status`).
- `TenantListener` (kernel.request, до RouterListener): по `Host` определяет бренд-тенант → кладёт в контекст (как `LocaleListener`). Если домен не наш каталог и есть в `tenant_domain` → режим «витрина тенанта».
- Подключение домена брендом: CNAME на наш edge + верификация (TXT/CNAME-запись) → `verified_at`.

### 3.2 Изоляция данных
- Тенант = `brand`. Товары/заказы/медиа уже FK на `brand` → выборки скоупить по тенант-бренду (глобальный Doctrine-фильтр `tenant` по `brand_id`, как soft-delete-фильтр).
- ЛК тенанта видит только свой бренд (роль `ROLE_BRAND_OWNER`, уже есть).

### 3.3 Роутинг витрины
- На тенант-домене корень `/` → витрина бренда (сейчас `/ru/brands/{slug}`), его товары, корзина, чекаут — без каталога wearbase.
- Свой `robots.txt`/`sitemap.xml` на домене тенанта (SEO раздельно от wearbase).

### 3.4 SSL для кастомных доменов (критично для SaaS)
- **Caddy / Traefik с on-demand TLS** (Let's Encrypt автоматически на каждый подключённый домен) перед приложением. On-demand TLS выдаёт сертификат при первом запросе на верифицированный домен. Ask-endpoint проверяет, что домен в `tenant_domain.verified`.
- Альтернатива: certbot + хук, но on-demand TLS (Caddy) проще для SaaS.

### 3.5 Биллинг — МОДЕЛЬ: минимальная база + всё остальное upsell (land-and-expand)
**Решение владельца:** базовая подписка по **минимальной сумме** (низкий барьер входа), **все фичи — платные допы (upsell)**. Зайти дёшево → монетизировать дополнениями.
- **Base (минимум/мес):** магазин на поддомене `brand.wearbase.shop`, готовый шаблон, базовая темизация (лого/цвет), приём заказов/оплат, каталог-трафик, базовый AI-контент. Цель — максимум подключений.
- **Upsell-каталог (каждый — отдельный платный add-on, докупается в ЛК):**
  - свой кастомный домен + SSL;
  - Pro-кастомизация (кастом-CSS/блоки/доп-страницы);
  - убрать «powered by Wearbase» (white-label);
  - расширенный AI-контент (больше генераций/перевод на N языков/FAQ-объём);
  - повышенный лимит товаров;
  - аналитика/расширенный SEO (sitemap-приоритеты, schema, GSC-интеграция);
  - **эксклюзив**: убрать товары бренда из общего каталога wearbase (только свой магазин) — для тех, кто хочет полную независимость/без соседства конкурентов;
  - приоритетная поддержка; доп-платёжки/рассрочка.
- **Дефолт (вариант А):** бренд остаётся в каталоге wearbase И имеет арендованный магазин → кросс-промо (каталог ловит покупателей → ведёт в т.ч. в его магазин). Это network-effect-козырь против Tilda. Выход из каталога — платный upsell (выше).
- Реализация: `Subscription` = база; допы — отдельные `feature flags`/`add-ons` на тенанте (таблица `tenant_addon(brand_id, feature, active, period)`), биллинг каждого через YooKassa. Гейт фич — по активным add-on'ам.
- Гейт магазина: активен при активной Base-подписке; просрочка → витрина → заглушка.

### 3.6 Кастомизация (тоже по модели upsell)
- **В базе:** общий Tailwind-шаблон + базовая темизация (лого, основной цвет, баннер) в ЛК.
- **Upsell:** Pro-кастомизация (кастом-CSS/блоки/доп-страницы about/доставка). Старт — «верстаем под заказ» (платно), позже — self-serve блоки-конструктор.

## 4. Этапы

1. **MVP:** tenant_domain + TenantListener + изоляция (Doctrine-фильтр) + витрина на поддомене `brand.wearbase.shop` (без кастом-доменов/SSL-возни) + гейт по подписке. Один бренд-пилот.
2. **Кастомные домены + on-demand SSL** (Caddy edge).
3. **Темизация в ЛК** (Base-кастомизация: лого/цвета/баннер).
4. **Pro-кастомизация** (платная) + тарифы в биллинге.
5. **Self-hosted** (опция, если будет спрос) — отдельная история (упаковка, лицензия, обновления).

---

## 5. Риски

| Риск | Защита |
|---|---|
| Конкуренция с Tilda/Shopify | НЕ generic-конструктор: вертикаль+сеть+AI+РФ-комплаенс (§1) |
| Сложность мультитенантности | тенант=бренд (изоляция почти есть); глобальный Doctrine-фильтр; пилот на 1 бренде |
| SSL на кастом-доменах | on-demand TLS (Caddy) — стандартное SaaS-решение |
| Утечка данных между тенантами | глобальный фильтр + тесты изоляции (тенант А не видит данные Б) |
| Поддержка/нагрузка | SaaS (мы хостим) управляемо; self-hosted отложен (там ад поддержки) |
| SEO-каннибализация | раздельные sitemap/robots/canonical на доменах тенантов |

## 6. Решения (финал, 06.06.2026)
- ✅ **MVP — на поддомене** `brand.wearbase.shop` (кастом-домены = upsell-этап 2).
- ✅ **Монетизация:** минимальная база + всё фичами-upsell (см. §3.5).
- ✅ **«powered by Wearbase»** по умолчанию есть; убрать (white-label) = upsell.
- ✅ **Каталог:** дефолт — вариант А (бренд и в каталоге wearbase, и в своём магазине → кросс-промо/трафик); выход из каталога (эксклюзив, только свой магазин) = upsell.
- ⏳ Осталось уточнить только конкретные цены (база/каждый add-on) — на этапе запуска.

## 7. Граница со «старым» wearbase
wearbase-каталог остаётся как есть (агрегатор+discovery). Аренда — надстройка: тот же код, но тенант-режим по домену. Один движок, две «морды»: каталог (wearbase.ru) и магазины-тенанты (их домены). Catalog ↔ tenant-store связаны (бренд из каталога → апселл аренды магазина).

## 8. Рынок / бенчмарк цен (RU, 2026)

| Платформа | Цена/мес | Заметки |
|---|---|---|
| Базиум | ~480₽ | дешёвый вход |
| **Tilda Business** | **1250₽** (старшие 2500–7500₽) | дизайн-first, нет трафика/вертикали/AI |
| **InSales** | **от 1720₽** | спец-e-comm, 50+ шаблонов, дороже |
| Ecwid | free + платные | виджет-магазин |
| Общий диапазон | **1500–5000₽/мес + эквайринг сверху** | |

**Чего у конкурентов НЕТ (наш wedge):** трафик/сеть каталога, РФ-фэшн-вертикаль, AI-контент из коробки, готовый РФ-комплаенс (YooKassa/оферты/юрлица), деньги напрямую бренду без комиссии с продаж.

**Рекомендация по цене (модель «минимум + upsell»):**
- **База ~490–790₽/мес** — НИЖЕ Tilda(1250)/InSales(1720): дёшево заходить (директива «минимальная сумма»), но база богаче (трафик каталога + AI + приём оплат через свою YooKassa). 
- **Допы à la carte** (домен, кастомизация, white-label, расширенный AI, эксклюзив-из-каталога) → расширенный чек у растущих ~1500–3000₽/мес = в рынке.
- Итог: вход дешевле всех, expand-чек в рынке; эквайринг бренд платит своему банку (мы комиссию с продаж не берём — отличие от маркетплейсов).
