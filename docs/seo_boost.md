# SEO Boost — GEO-листиклы «ТОП-N в нише» (`app:seo:listicle`)

Команда `app:seo:listicle` — внутренняя реализация платной услуги ContentMagic
«SEO Boost» (КП на 130 000 ₽ за 20 статей; расшифровка и разбор — в
`~/Downloads/KP_SEO_Boost.md`). Генерирует статью-рейтинг «ТОП-N лучших брендов в
нише», где **целевой бренд стоит на 1-м месте**, а остальные места занимают
реальные конкуренты той же ниши из каталога.

## Зачем

Двойной эффект для целевого бренда:

- **GEO** (Generative Engine Optimization) — листиклы на авторитетных площадках
  цитируются LLM (ChatGPT/Perplexity/Gemini/YandexGPT) в ответах на «какой лучший
  бренд X». Бренд попадает в эти ответы.
- **SEO** — статья на внешнем домене + `ItemList` JSON-LD со ссылками на страницы
  брендов в каталоге → бэклинки на wearbase.ru + захват выдачи.

Себестоимость ≈ 0 (генерация на локальной ollama). Основная инвестиция — не
генерация, а **публикация** (см. «Что НЕ автоматизировано»).

> ⚠️ Статья предназначена для **внешних** площадок (vc.ru, dtf.ru, Пикабу,
> telegra.ph, press-release.ru …), а **НЕ** для wearbase.ru: self-домен не даёт
> SEO-эффекта обзора и исключается `UrlFilter` из скрейпа.

## Как работает

```
целевой бренд + ниша
   │
   ├─ ниша = BrandStyle  (НЕ Category — см. «Важно: ниша = стиль»)
   ├─ конкуренты = BrandRepository::findListicleCompetitors(styleId, …)
   │     активные, та же ниша, описание >100 симв., сорт. по длине описания DESC
   │
   ├─ факты по каждому бренду = описание + BrandRagService::retrieve() (grounded-gate)
   ├─ ключевики целевого = BrandKeyword::findByBrandRanked (Wordstat) → SEO-вплетение
   ├─ FAQ целевого = LlmService::generateBrandFaq (Wordstat-фразы → grounded Q/A)
   │
   └─ на каждый вариант:
        LlmService::generateListicle(ниша, [целевой, ...конкуренты], персона, тон, ключи)
          → markdown-тело (intro → ## N. Бренд → вывод)
        + ## Частые вопросы (markdown)
        + JSON-LD @graph: Article + ItemList + FAQPage   ← строится в коде, не LLM
```

Всё **grounded**: описания секций — строго из фактов бренда (описание + RAG-корпус),
без выдуманных цен/дат/сравнений. FAQ-ответы — только из фактов (`generateBrandFaq`
пропускает фразы без опоры).

## Использование

```bash
# Ниша auto (первый стиль бренда), вывод в консоль
php bin/console app:seo:listicle 354

# Ниша по slug стиля, ТОП-5 на vc.ru, сохранить .md
php bin/console app:seo:listicle 354 streetwear --top=5 --platform=vc --out=var/seo

# Пакет из 5 статей: ротация персон/площадок/порядка конкурентов
php bin/console app:seo:listicle 354 auto --variants=5 --out=var/seo

# Без FAQ-блока
php bin/console app:seo:listicle 354 auto --no-faq --out=var/seo
```

### Аргументы и опции

| Параметр | По умолчанию | Назначение |
|---|---|---|
| `brand` (арг) | — | ID целевого бренда (место №1) |
| `niche` (арг) | `auto` | Slug стиля-ниши; `auto` — первый стиль бренда |
| `--top` | `5` | Сколько мест в рейтинге (2..10) |
| `--platform` | `vc` | Площадка/тон: `vc` \| `dtf` \| `pikabu` \| `press` \| `blog` |
| `--persona` | `0` | Индекс автора-персоны (0..5) |
| `--variants` | `1` | Сколько статей сгенерить (ротация персон/площадок/порядка) |
| `--no-faq` | — | Не добавлять FAQ-блок и FAQPage JSON-LD |
| `--out` | — | Папка для `.md` (без неё — вывод в консоль) |

**Имя файла:** `listicle-{style}-{target}-{platform}-p{persona}.md` — варианты не
перетирают друг друга.

### Персоны (`--persona`, ротация при `--variants`)

`0` fashion-стилист · `1` маркетолог fashion-ритейла · `2` блогер про осознанное
потребление · `3` журналист о моде · `4` предприниматель e-commerce · `5`
покупатель-энтузиаст. Разный голос → статьи не близнецы.

### Площадки/тон (`--platform`)

`vc` экспертный аналитический обзор · `dtf` личный тест-эксперимент · `pikabu`
личный опыт (UGC) · `press` пресс-релиз · `blog` личный блог.

### Что даёт `--variants=N`

На каждый вариант ротируются **автор-персона**, **площадка/тон** и **порядок
конкурентов** (целевой всегда №1). FAQ и факты считаются один раз (не зависят от
площадки) → N статей дешевле, чем N запусков. Имитирует обещание КП «20 уникальных
статей от разных авторов».

## Важно: ниша = стиль (`BrandStyle`), не категория

Ниша берётся из **`BrandStyle`**, а не из `Category`: таблица `brand_category` в
каталоге **пуста**, тогда как `brand_style_brand` заполнена (streetwear ≈ 68,
повседневный ≈ 60, минимализм ≈ 20 …). Если перейдём на категории — менять
`BrandRepository::findListicleCompetitors` и `resolveStyle` в команде.

## Где что в коде

| Где | Что |
|---|---|
| `src/Command/GenerateListicleCommand.php` | команда: выборка, подготовка фактов/FAQ один раз, цикл вариантов, JSON-LD, сохранение |
| `src/Service/LlmService.php::generateListicle()` | grounded-промпт листикла (порядок мест, факты, персона, тон, ключи) |
| `src/Service/LlmService.php::generateBrandFaq()` | FAQ из Wordstat-фраз (переиспользуется из задачи FAQ) |
| `src/Repository/BrandRepository.php::findListicleCompetitors()` | конкуренты той же ниши с описанием |

JSON-LD (`Article` + `ItemList` + `FAQPage` в `@graph`) собирается **в коде**
детерминированно — модели не доверяем структурную разметку.

## Известные нюансы (проверять перед публикацией)

- **Шум модели в тексте**: возможны опечатки имён («TEKK_KAI», «Магической битлы»)
  и буквальное вплетение ключа строчными (`**tekkai**`). Это артефакты локальной
  LLM, не баг команды — статью перед публикацией **вычитывать**.
- Факты ограничены `MAX_FACTS_PER_BRAND = 2500` символов на бренд (контроль длины
  промпта). У брендов без RAG-корпуса секция строится только из описания.
- Конкуренты требуют описание >100 символов: если в нише их нет — команда падает с
  понятной ошибкой, выберите другую нишу/`--top` поменьше.

## Этика и право (КП-фон)

- **Маркировать рекламу** (ФЗ о рекламе РФ, ОРД) там, где это реклама.
- Рейтинг — **на реальных фактах** (grounded), а не «мы №1 всегда»: это снижает
  риск бана модерацией площадок и честнее. См. [[marketing_seo.md]] про GEO/FAQ.

## Что НЕ автоматизировано (следующие шаги)

1. **Публикация** на площадки — самый ручной этап: у vc.ru/dtf.ru/pikabu нет
   публичного API. Начинать с автоматизируемых (telegra.ph, pastelink.net,
   press-release.ru), остальное — браузерная автоматизация / ручной плейбук.
2. **Мониторинг индексации** — попадание URL в индекс (GSC уже подключён,
   `app:gsc:sync`) + опрос AI «какой лучший X» для контроля цитирования.
