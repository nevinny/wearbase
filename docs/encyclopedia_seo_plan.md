# Энциклопедия + перелинковка (SEO-приём getboat / GetRentacar)

> Источник идеи: голосовое от 2026-07-09. На **getboat.com** (аренда яхт) и планово на
> GetRentacar реализована «энциклопедия» моделей с двусторонней перелинковкой к
> коммерческим карточкам — по словам заказчика, «супер-эффективно, Google очень нравится».
> Аналог itboat.com: 8633 модели × 1071 производитель × 70 типов, у каждой модели годы
> выпуска модельного ряда. Здесь — как применить к WEARBASE.

## Реальная схема getboat.com (сверено вживую 2026-07-09)

Три уровня, все перелинкованы:

1. **Хаб `/encyclopedia`** — «Boat & Yacht Brands — builders A–Z». H1 + подзаголовок
   «their history and heritage, with 62 brands and 1,547 listings». Сетка карточек
   производителей: лого + счётчик листингов (напр. «161») + 1 строка дефиниции
   («Sunseeker International has built performance motor yachts in Poole…») + «Explore →».
2. **Страница производителя `/encyclopedia/{slug}`** (напр. `/encyclopedia/sunseeker`),
   `<title>` = «Sunseeker — boats, yachts & brand history»:
   - крошки «← All brands», лого + «161 boats on GetBoat»;
   - интро с фактами-якорями: «built … **since 1969**, current range from 55 to 134 foot»;
   - **H2 с годами-якорями** — «From Poole Power Boats to Sunseeker International»
     (основан **1969** → переименован **1985** → Wanda Group **2013** → сделка **2024**);
   - H2 «The … range today» (модельный ряд), H2 «Charter fleets and the used … market»;
   - грид карточек в аренду «{Brand} boats on GetBoat», **каждая озаглавлена ГОДОМ
     выпуска** («2015, Sunseeker Portofino 40», «2003, Fantastic Prestige») + «Browse all →».
3. **Карточка листинга `/boat/{slug}`** — содержит **обратную ссылку
   «Sunseeker in the encyclopedia» → `/encyclopedia/sunseeker`** (+ дубль в футере
   «Popular boat brands»). Это и есть «с карточки обратно в энциклопедию».

Плюс отдельный SEO-футер с фасетами: destinations, boat types, ports, popular brands.

**Ключевой вывод:** победный приём — **две индексируемые страницы на одну сущность**
(коммерческая карточка + энциклопедическая история), плотно **перелинкованные в обе
стороны**, где энциклопедия несёт уникальный факт-контент с **годами-якорями**. Именно
удвоение поверхности + перелинковка + grounded-история «нравятся Google».

## Суть приёма (hub-and-spoke через энциклопедию)

- **Коммерческий слой**: карточки «арендовать лодку/машину» — конвертят, но тонкие и
  похожие (риск thin/duplicate content).
- **Информационный слой (энциклопедия)**: страницы-сущности «что это» — модель, верфь/марка,
  тип, **годы выпуска (с YYYY по YYYY)**, характеристики. Evergreen, уникальный факт-контент.
- **Двусторонние ссылки**: карточка → «изучить модель в энциклопедии»; энциклопедия → все
  карточки этой модели в аренду. Плотный внутренний граф + осмысленные якоря + тематический
  авторитет. Ключ, «который любит Google»: **год выпуска** — факт-якорь, вокруг которого
  нельзя нагенерить дубли, и естественная перелинковка инфо↔коммерц.

## Перенос на WEARBASE (каталог брендов одежды)

Наш `Brand` = «производитель» getboat. Значит **прямой, проверенный порт** — вариант B
ниже (энциклопедия-история бренда). Вариант A (глоссарий одежды) — это уже наше
расширение поверх (getboat такого не делает; их «boat types» = коммерческие фасеты,
у нас уже закрыты `/styles`, `/cities`).

### B. Энциклопедия-история бренда — ПРЯМОЙ ПОРТ getboat (приоритет №1)
Схема 1:1: на каждый бренд — **вторая индексируемая страница** `/encyclopedia/{slug}`
(история/наследие), отдельная от коммерческой `/brands/{slug}`, перелинкованные в обе
стороны. Именно удвоение + перелинковка даёт эффект.
- Хаб `/encyclopedia` — бренды A–Z с фреймингом «история и наследие» (можно переиспользовать
  `Alphabet`), но это ОТДЕЛЬНЫЙ инфо-URL, не коммерческий `/brands`.
- Страница `/encyclopedia/{slug}` — интро с фактами (`foundingYear` → «с YYYY года»),
  **H2 с годами-якорями** (основан → вехи → сегодня / закрыт через `closedAt`), затем
  грид коммерческих карточек товаров бренда + CTA «смотреть в каталоге».
- Обратная ссылка на `/brands/{slug}`: «изучить историю бренда в энциклопедии».
- **Гэп**: историю/вехи хранить негде (только `foundingYear`) → нужно TEXT-поле `history`
  или мини-сущность `BrandMilestone (year, event)`; заполнять **grounded из RAG-корпуса**
  (не галлюцинировать — у закрытых/малоизвестных брендов истории может не быть → тогда
  страницу НЕ плодим, иначе thin/scaled-content дубль).
- **Риск**: две страницы на бренд = дубль, если история пустая/слабая. Гейт качества:
  страница энциклопедии рождается только при достаточном grounded-контенте (аналог gate
  в RAG-конвейере chunks≥3 И score≥0.5).

### A. Энциклопедия одежды (глоссарий) — наше расширение (приоритет №2)
«Модель лодки» ⇒ **термин одежды**: тип вещи (худи, тренч, оверсайз, карго), материал
(деним, кашемир, лён), стиль (минимализм, стритвир), сегмент/аудитория. Каждая страница —
дефиниция + «какие бренды WEARBASE это делают».

Инвентарь терминов **уже лежит в данных** — не выдумываем:
- `BrandAttribute` (key-value): `NAME_STYLE / NAME_CATEGORY / NAME_MATERIAL / NAME_GENDER /
  NAME_PRICE_SEGMENT / NAME_GEO` — каждое уникальное `value` = кандидат в страницу энциклопедии.
- Нормализованные справочники: `BrandStyle`, `BrandAudience`, `BrandTier`, `BrandSize`,
  `Category` (все ManyToMany с Brand).

Частично **уже реализовано**: хабы `/style/{slug}` и `/cities/{slug}` — это де-факто
энциклопедические листинги стиля/города (список брендов). Не хватает: (1) дефиниционного
интро, (2) `DefinedTerm` JSON-LD, (3) **обратной ссылки с карточки бренда** «изучить стиль X».

### B. История/таймлайн бренда — прямой аналог «годов выпуска»
«С YYYY по YYYY» ⇒ **год основания + таймлайн бренда** (основан → вехи → сейчас / закрыт).
- Уже есть: `Brand.foundingYear` (string4) и `Brand.closedAt` + `isClosed()`; `foundingYear`
  уже уходит в `Organization.foundingDate` (JSON-LD).
- Не хватает **места хранить историю/вехи** — кроме одного `foundingYear` полей нет. Нужен
  либо TEXT-поле `history`, либо мини-сущность `BrandMilestone` (year, event). Заполнять
  через RAG-конвейер (grounded, из собранного корпуса — не галлюцинировать).
- Даёт уникальный факт-блок на карточке + усиливает Organization schema.

## Что переиспользуем (уже в проде)

| Готовый актив | Как использовать |
|---|---|
| `brand_related` + `BrandLinkGraphService` (OUT_DEGREE=12, источники embedding>style>city>fill) | Расширить граф рёбрами **бренд↔термин** энциклопедии |
| Таксо-хабы `/style/{slug}`, `/cities/{slug}`, `Category` | Достроить до полноценных энциклопедических страниц (интро + schema + обратные ссылки) |
| `Article` + `Author` (E-E-A-T, байлайн, JSON-LD) | Движок для длинных энциклопедических статей, если решим не плодить новую сущность |
| `BrandFaq` + `FAQPage` JSON-LD (генерятся из Wordstat) | FAQ на страницах терминов; вопросы из Wordstat по термину |
| RAG-конвейер (discover→fetch→embed→generate) + Wordstat | Grounded-генерация дефиниций терминов и истории брендов; title из топ-фразы Wordstat |
| JSON-LD инфраструктура в Twig | Добавить `DefinedTerm` / `Article` для энциклопедии |

## Гэпы

1. Нет сущности Encyclopedia/Term/Glossary — чистое поле (плюс: не ломаем существующее).
2. Историю бренда хранить негде (только `foundingYear`) — нужно поле/сущность.
3. Обратной ссылки «карточка → энциклопедия» нет — сейчас граф только бренд↔бренд.

## Предлагаемая последовательность (от дешёвого к дорогому)

- **Фаза 0 (разведка) — ✅ сделано 2026-07-09**: снята реальная схема getboat.com
  (см. раздел выше) — 3 уровня, двусторонняя перелинковка, годы-якоря подтверждены.
- **Фаза 1 = вариант B (прямой порт, приоритет)**: хранилище истории (`history` /
  `BrandMilestone`) → grounded-генерация из RAG-корпуса с гейтом качества → страница
  `/encyclopedia/{slug}` (интро+год-якорь+H2 истории+грид товаров) → хаб `/encyclopedia`
  (A–Z) → **двусторонняя ссылка** `/brands/{slug}` ↔ `/encyclopedia/{slug}` → `Article`/
  `AboutPage` + усиление `Organization.foundingDate` JSON-LD → sitemap только для брендов
  с реальной историей (не плодить пустышки).
- **Фаза 2 = вариант A (глоссарий одежды)**: апгрейд таксо-хабов до энциклопедии —
  RAG-интро + `DefinedTerm` JSON-LD + обратная ссылка на карточке «изучить стиль/материал X».
  Инвентарь страниц из реальных значений `BrandAttribute` (style/category/material).
- **Фаза 3**: рёбра бренд↔термин в графе; перелинковка терминов между собой
  (материал↔стиль↔категория); фасетный SEO-футер как у getboat.

## Метрика успеха
Рост индексируемых URL (энциклопедия) + рост внутренних ссылок на карточки брендов +
показы/клики в GSC по информационным запросам («что такое …», «бренды … стиля»).
Смотреть в связке с `docs/seo_adoption_plan.md` (жёсткий граф) и `docs/seo_boost.md`.
