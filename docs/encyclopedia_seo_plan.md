# Энциклопедия + перелинковка (SEO-приём getboat / GetRentacar)

> Источник идеи: голосовое от 2026-07-09. На **getboat.com** (аренда яхт) и планово на
> GetRentacar реализована «энциклопедия» моделей с двусторонней перелинковкой к
> коммерческим карточкам — по словам заказчика, «супер-эффективно, Google очень нравится».
> Аналог itboat.com: 8633 модели × 1071 производитель × 70 типов, у каждой модели годы
> выпуска модельного ряда. Здесь — как применить к WEARBASE.

## Суть приёма (hub-and-spoke через энциклопедию)

- **Коммерческий слой**: карточки «арендовать лодку/машину» — конвертят, но тонкие и
  похожие (риск thin/duplicate content).
- **Информационный слой (энциклопедия)**: страницы-сущности «что это» — модель, верфь/марка,
  тип, **годы выпуска (с YYYY по YYYY)**, характеристики. Evergreen, уникальный факт-контент.
- **Двусторонние ссылки**: карточка → «изучить модель в энциклопедии»; энциклопедия → все
  карточки этой модели в аренду. Плотный внутренний граф + осмысленные якоря + тематический
  авторитет. Ключ, «который любит Google»: **год выпуска** — факт-якорь, вокруг которого
  нельзя нагенерить дубли, и естественная перелинковка инфо↔коммерц.

## Перенос на WEARBASE (каталог брендов одежды)

Два независимых аналога — можно делать по отдельности:

### A. Энциклопедия одежды (глоссарий) — новый SEO-поверхностный слой
«Модель лодки» ⇒ **термин одежды**: тип вещи (худи, тренч, оверсайз, карго), материал
(деним, кашемир, лён), стиль (минимализм, стритвир), сегмент/аудитория. Каждая страница —
дефиниция + «какие бренды WEARBASE это делают».

Инвентарь терминов **уже лежит в данных** — не выдумываем:
- `BrandAttribute` (key-value): `NAME_STYLE / NAME_CATEGORY / NAME_MATERIAL / NAME_GENDER /
  NAME_PRICE_SEGMENT / NAME_GEO` — каждое уникальное `value` = кандидат в страницу энциклопедии.
- Нормализованные справочники: `BrandStyle`, `BrandAudience`, `BrandTier`, `BrandSize`,
  `Category` (все ManyToMany с Brand).

Частично **уже реализовано**: хабы `/style/{slug}` и `/cities/{slug}` — это де-факто
энциклопедические листинги стиля/города (список брендов). Не хватает: (1) дефиниционного
интро, (2) `DefinedTerm` JSON-LD, (3) **обратной ссылки с карточки бренда** «изучить стиль X».

### B. История/таймлайн бренда — прямой аналог «годов выпуска»
«С YYYY по YYYY» ⇒ **год основания + таймлайн бренда** (основан → вехи → сейчас / закрыт).
- Уже есть: `Brand.foundingYear` (string4) и `Brand.closedAt` + `isClosed()`; `foundingYear`
  уже уходит в `Organization.foundingDate` (JSON-LD).
- Не хватает **места хранить историю/вехи** — кроме одного `foundingYear` полей нет. Нужен
  либо TEXT-поле `history`, либо мини-сущность `BrandMilestone` (year, event). Заполнять
  через RAG-конвейер (grounded, из собранного корпуса — не галлюцинировать).
- Даёт уникальный факт-блок на карточке + усиливает Organization schema.

## Что переиспользуем (уже в проде)

| Готовый актив | Как использовать |
|---|---|
| `brand_related` + `BrandLinkGraphService` (OUT_DEGREE=12, источники embedding>style>city>fill) | Расширить граф рёбрами **бренд↔термин** энциклопедии |
| Таксо-хабы `/style/{slug}`, `/cities/{slug}`, `Category` | Достроить до полноценных энциклопедических страниц (интро + schema + обратные ссылки) |
| `Article` + `Author` (E-E-A-T, байлайн, JSON-LD) | Движок для длинных энциклопедических статей, если решим не плодить новую сущность |
| `BrandFaq` + `FAQPage` JSON-LD (генерятся из Wordstat) | FAQ на страницах терминов; вопросы из Wordstat по термину |
| RAG-конвейер (discover→fetch→embed→generate) + Wordstat | Grounded-генерация дефиниций терминов и истории брендов; title из топ-фразы Wordstat |
| JSON-LD инфраструктура в Twig | Добавить `DefinedTerm` / `Article` для энциклопедии |

## Гэпы

1. Нет сущности Encyclopedia/Term/Glossary — чистое поле (плюс: не ломаем существующее).
2. Историю бренда хранить негде (только `foundingYear`) — нужно поле/сущность.
3. Обратной ссылки «карточка → энциклопедия» нет — сейчас граф только бренд↔бренд.

## Предлагаемая последовательность (от дешёвого к дорогому)

- **Фаза 0 (разведка, ~0)**: снять реальный HTML энциклопедии getboat.com (URL-паттерн,
  якоря, схема перелинковки) — свериться с оригиналом. Сейчас блокирует JS-рендер, нужен
  браузер/прод-краул.
- **Фаза 1 (макс. рычаг, мин. риск)**: апгрейд существующих таксо-хабов до энциклопедии —
  RAG-интро + `DefinedTerm` JSON-LD + **обратная ссылка на карточке бренда** «изучить стиль/
  категорию X». Расширить с стилей на материалы и типы одежды (из `BrandAttribute`).
  Инвентарь страниц авто-генерится из реальных значений атрибутов (как getboat из каталога).
- **Фаза 2**: таймлайн/история бренда (новое поле `history` или `BrandMilestone`) —
  grounded из RAG-корпуса; усиление Organization schema; блок на карточке.
- **Фаза 3**: рёбра бренд↔термин в `brand_related`/новом графе; sitemap + внутренняя
  перелинковка терминов между собой (материал↔стиль↔категория).

## Метрика успеха
Рост индексируемых URL (энциклопедия) + рост внутренних ссылок на карточки брендов +
показы/клики в GSC по информационным запросам («что такое …», «бренды … стиля»).
Смотреть в связке с `docs/seo_adoption_plan.md` (жёсткий граф) и `docs/seo_boost.md`.
