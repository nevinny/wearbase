# Верификация владения брендом — варианты и решение

> Разведка 2026-07-30. Повод: автономное самообслуживание каталога (бренд регистрируется сам,
> конвейер проверяет и публикует без человека). Нужен барьер против бренд-сквоттинга и спама,
> не отпугивающий настоящие малые бренды.
> Связанные документы: [brand_self_service.md](brand_self_service.md), [foreign_brands_policy.md](foreign_brands_policy.md).

## Задача, которую решаем

Детерминированный матчер (`App\Service\Moderation\ApplicationMatcher`) сверяет телефон/email/адрес
заявки с найденным в интернете сайтом. Это доказывает, что **такой бренд существует**
(`identity_match`), но **не** что заявитель им владеет: публичные контакты копируются с сайта в
один клик. Отсюда вторая, ортогональная ось — `control_proof`.

**Ключевое ограничение (реальный кейс).** У настоящего бренда AX! (ahsilk.ru) регистрационная почта
на `yandex.ru`, а не на своём домене. У малых российских брендов корпоративной почты обычно нет.
Значит «email на домене сайта» как единственный барьер отсекает именно тех, кого мы хотим.

## Как это делают другие (2025–2026)

| Кто | Что требует | Что это доказывает |
|---|---|---|
| **Trustpilot** | 4 **равноправных** способа: почта на домене, DNS TXT, HTML-файл в корне, Google Search Console | владение доменом; домен-верификация включается именно когда почта не на домене |
| Google Business Profile | видео-обход помещения (дефолт 2026), телефон/SMS «если eligible», открытка реже, instant при домене в Search Console | существование физического бизнеса |
| Crunchbase / LinkedIn | только корпоративная почта на домене | этот барьер завалил бы ahsilk.ru |
| Clutch | кредитная проверка CreditSafe + регданные, $499/год | платная верификация организации |
| Яндекс Бизнес | код **звонком/SMS на телефон из карточки** (5 мин), документы — эскалация | контроль публичного телефона организации |
| 2ГИС | «Это моя компания» → звонок или документы, 3–10 дней | то же |
| Wildberries / Ozon | ИНН + автосверка с ФНС, паспорт, реквизиты (WB — взнос 10 000 ₽, Ozon — вход через Госуслуги) | юр. субъектность продавца |
| Авито Бизнес | ИНН + автоподтяжка из реестров, penny-drop банковским переводом | владение счётом юрлица |
| Ankorstore | зарегистрированная компания + счёт + KYC через Stripe Identity, ревью 48 ч | KYC |
| **Not Just A Label** | верификации владения **нет вообще**, самообслуживание бесплатно, монетизация подпиской | — |

**Вывод.** «Почта на домене» как единственный барьер — практика B2B-баз (Crunchbase/LinkedIn), а не
каталогов с самообслуживанием. Каталоги дают **набор равнозначных способов**, проверяют
личность/организацию, а **права на бренд — реактивно, по жалобе** (WB требует свидетельство на ТЗ
только для бейджа «Оригинал», Ozon не спрашивает ничего до претензии). Модель Trustpilot —
ближайшая к нашей.

## Телефонная верификация в РФ: цены (июль 2026)

| Канал | Цена за подтверждение | Источник |
|---|---|---|
| SMS (SMSC, тариф с 01.08.2026) | МТС 5.70 ₽ · Tele2 7.83 ₽ · МегаФон 10.30–11.10 ₽ | smsc.ru/tariffs |
| SMS (SMS Aero, базовый) | от 2.2 ₽ + НДС 22 % | smsaero.ru/price/sms |
| **Голосовой код (SMSC, 5 сек)** | **0.25–0.33 ₽** | smsc.ru/tariffs |
| Flash call (Zvonok) | 1.83 ₽ | zvonok.com |
| **Telegram Gateway (напрямую)** | **$0.01 (~0.8 ₽)**, бесплатно если номера нет в TG, автовозврат при недоставке | core.telegram.org/gateway |
| Telegram через реселлеров | 1.55–1.80 ₽ | smsc.ru · i-dgtl.ru |
| **TG-бот `request_contact`** | **0 ₽** | Bot API KeyboardButton |

Flash call дешевле SMS в 5–10 раз, голосовой код — в 10–40 раз. Доставляемость Telegram Gateway в
РФ оценивают в 50–70 % и нужен интернет у пользователя. TG-бот бесплатен, но работает только в
приватном чате; как proof годится при сверке `contact.user_id == from.id` (номер привязан к самому
TG-аккаунту). У нас уже есть @wearbase_bot — инфраструктура на месте.

⚠️ **Что телефон доказывает:** только владение SIM/аккаунтом. Против бренд-сквоттинга бесполезен
(сквоттер вводит свой номер). Полезен против массовой автоматизации — как антибот, а не как proof
владения брендом.

**Решение: SMS → бэклог.** Проигрывает по цене в 3–13 раз при том же смысле.

## Дешёвые доказательства связи с брендом

| Способ | Что даёт | Пригодность |
|---|---|---|
| **Яндекс ID OAuth** (`login:default_phone`) | верифицированный номер бесплатно | да — бесплатная замена SMS на входе |
| **VK ID OAuth** | маскированный телефон в ID token, полный по access token | да, там же |
| **Код на email, найденный НАШИМ скрейпом на сайте бренда** | контроль канала, который бренд сам публикует | **да — главный способ**; работает при почте на yandex.ru |
| **DNS TXT / файл в корне домена** | владение доменом (модель Trustpilot) | да, 0 ₽ |
| **Код из соцаккаунта, на который ссылается сайт бренда** | контроль соцканала; связь «сайт → аккаунт» обязательна | да, 0 ₽ |
| **DaData** (организация/ИП по ИНН/ОГРН) | существование юрлица/ИП | да — **10 000 запросов/сутки бесплатно** |
| **npd.nalog.ru** (статус самозанятого по ИНН) | статус НПД | да, бесплатно без регистрации, лимит 2 запроса/мин с IP |
| ЕГРЮЛ официально (ФНС) | выписки | нет: FTP + клиентский сертификат + абонентское обслуживание |
| ЕСИА / Госуслуги | верифицированная личность/юрлицо | **нет**: СКЗИ не ниже КС3 с сертификацией ФСБ + аттестация ИС |
| Роспатент / ФИПС | права на товарный знак | только по спору: у малых брендов ТЗ обычно нет, бесплатной программной сверки не подтвердил |

## Обратная ссылка: гипотеза владельца верна, но по другой причине

Google в spam policies прямо перечисляет как link spam: «*Requiring a link as part of a Terms of
Service, contract, or similar arrangement without allowing a third-party content owner the choice of
qualifying the outbound link*», плюс «excessive link exchanges» и «low-quality directory links».

То есть обязательный backlink за листинг — риск **для нас** (весь профиль каталога), а не только
для бренда. Данных о конверсии такого требования не найдено.

**Решение: обязательным барьером не делать.** Допустимо — опциональный badge за бонус (приоритет в
каталоге / расширенная карточка) с явным разрешением поставить `rel="nofollow"`: тогда формулировка
Google не нарушается.

## Принятая лестница

Принцип: **якорь доверия — то, что уже опубликовано на сайте бренда, а не то, что ввёл заявитель.**
Это единственный вид барьера, который держит сквоттинг и при этом проходится брендом с почтой на
yandex.ru.

**L0 — регистрация** (0 ₽, авто, публикации нет). Вход через Яндекс ID / VK ID (верифицированный
телефон бесплатно) либо код на любую почту. Результат — карточка в карантине: `noindex`, не в
sitemap, исходящие ссылки `nofollow sponsored`, не в листингах и перелинковке.

**L1 — авто-публикация** (0 ₽). Достаточно **любого одного**:
1. код на email, **найденный нашим скрейпом на сайте бренда** (не введённый заявителем);
2. DNS TXT-запись или файл в корне домена бренда;
3. код в посте/сторис/DM из соцаккаунта, **на который ссылается сайт бренда**;
4. ИНН + автосверка DaData / npd.nalog.ru при совпадении названия.

**L2 — эскалация** (по подозрению или жалобе). Telegram Gateway (~0.8 ₽) или голосовой код
(0.25–0.33 ₽) как антибот при аномалиях; свидетельство на ТЗ / выписка ЕГРЮЛ — только по спору
(модель Ozon).

Право **продавать** (`SellerLegalEntity` / `SellerPaymentAccount`) открывается только на L1+ — это
и есть разрыв между «карточку публикуем» и «к деньгам пускаем».

## Что из этого уже реализовано в проекте

Не строить заново — см. [brand-claim-verification.md](brand-claim-verification.md) (реализация) и
[antifraud_plan.md](antifraud_plan.md) (риски):

| Способ из лестницы | Состояние | Где |
|---|---|---|
| Код на email бренда | **готово**, TTL 15 мин, cooldown 60 с, лимиты 5/5, `hash_equals`, CSRF | `BrandClaimService::startEmailCode()` |
| Контроль соцаккаунта (VK-админ) | **code-complete, вживую не проверено**; нужны `VK_APP_ID`/`VK_APP_SECRET` | `VkVerifier.php`, OAuth 2.1 + PKCE |
| Документы (ТЗ/ИНН), кабинет маркетплейса, Telegram-бот, SMS | не реализованы | — |

⚠️ **Критичная поправка для самрега (расхождение с реализацией).** `startEmailCode()` шлёт код на
`brand.email` **из нашей БД**. Для каталожного бренда это адрес, добытый обогащением с его сайта —
и тогда метод корректен. Для **самозарегистрированного** бренда `brand.email` ввёл сам заявитель,
поэтому отправка кода туда доказывает только то, что он владеет своей же почтой — **как proof
контроля это ноль**. Для самрега адрес обязан браться свежим скрейпом официального сайта, а не из
профиля. Это и есть разница между `identity_match` и `control_proof`.

⚠️ **Авто-грант включён на проде**: `BRAND_CLAIM_AUTOGRANT_EMAIL=1`, `BRAND_CLAIM_AUTOGRANT_VK=1`
(`.env:70-71`). Любой, кто подтвердит контроль над `brand.email`, **мгновенно получает владение без
ревью человеком** — включая перехват брошенных карточек с устаревшим enrichment-адресом. При переходе
к автономии это главный вектор сквоттинга по 3.6k бесхозным карточкам: он не требует ни сайта, ни
документов. Решение — не выключать авто-грант целиком (это вернёт ручную работу), а различать
карточки: авто-грант допустим только когда адрес подтверждён скрейпом живого сайта бренда и у
карточки нет истории трафика/кликов.

## В бэклог как дорогое или сложное

SMS-верификация (проигрывает по цене в 3–13 раз) · ЕСИА (СКЗИ КС3, аттестация) · FTP-интеграция
ЕГРЮЛ · penny-drop как у Авито · платная верификация как Clutch ($499/год) · видео-верификация как
Google Business Profile.
