# WEARBASE — handoff для Codex

Дата: 2026-07-06. Готовим передачу разработки нового функционала другому AI-агенту (Codex).
Этот файл — самодостаточная точка входа: что за проект, где что лежит, что нельзя делать не думая.

## Что это

WEARBASE — каталог российских брендов одежды (~779 подтверждённых брендов + ~5400 из Lamoda,
требуют классификации по происхождению) с прицелом на международные рынки. Модель: бесплатная
витрина брендов + платные услуги продвижения (0% комиссии с продаж — деньги идут напрямую бренду,
не через платформу). SEO/GEO — основной канал роста; параллельно строится RAG-конвейер генерации
контента брендов из реальных фактов (не выдумки LLM).

## Стек

Symfony 7.3 · PHP 8.2+ · MySQL 9.1 · Doctrine ORM · EasyAdmin 4 · Twig · AssetMapper (без Webpack/Vite).
Tailwind через CDN (`cdn.tailwindcss.com`), Bootstrap полностью удалён 2026-06-12 — не восстанавливать.
`public_html/` — публичная директория (не `public/`, см. `composer.json`).

## Жёсткие правила проекта (не нарушать)

- **Soft-delete только.** Никакого физического `DELETE` по действию пользователя — только через
  `status = Statuses::Deleted` (трейт `Status`) или `deleted_at`. Выборки обязаны фильтровать
  удалённое. Физический DELETE — только в миграциях/системных импортах.
- **Миграции**: `CREATE TABLE IF NOT EXISTS` + `INSERT IGNORE` для идемпотентности, описательные
  имена (`Version20260523_phase5_brand_market.php`). Никогда `doctrine:schema:update`.
- **Два firewall, два User** — `/admin` → `Nevinny\AdminCoreBundle\Entity\User`, `/*` → `App\Entity\User`.
  Не путать роуты логина/логаута между ними.
- **`country.id` — `INT UNSIGNED`.** Любой FK на неё обязан быть тоже `INT UNSIGNED NOT NULL`,
  иначе MySQL error 3780. `brand.id`/`product.id` — обычный signed `INT`.
- **Цены — только в RUB в БД.** Конвертация на лету через `CurrencyConverter`, фильтр `|price` в
  Twig. Никогда не хранить конвертированные суммы.
- Долгие батч-команды (сотни+ записей) — обязательно с `--no-debug` (Doctrine-профайлер копит
  backtrace каждого SQL-запроса в памяти → OOM на ~750 записях при 512M).

## Архитектурные точки, о которые обычно спотыкаются

- Локаль резолвится `LocaleListener`: cookie → `Accept-Language` → default из таблицы `language` →
  fallback `ru`. Не-ru локали сейчас все `noindex,follow` (переводов нет, отдают ru-контент как
  fallback) — см. `docs/international.md`.
- Два Twig-layout: `tailwind/base.html.twig` (публичные SEO-страницы) и `tailwind/app.html.twig`
  (auth/аккаунт/ЛК бренда/checkout, `noindex`). Не смешивать.
- `brand_t()` / `product_t()` в Twig — переводы с fallback на русский оригинал, не писать вручную.
- RAG-конвейер (`discover → fetch → embed → generate-content`) живёт на отдельном LLM-сервере
  (ollama/Qdrant/SearXNG), IP которого нестабилен — если трогаешь генерацию контента, читай
  `docs/rag_pipeline.md` целиком, там весь gotcha-список.

## Что НЕ нужно для типовой разработки фичи

`OPENROUTER_API_KEY`, доступ к LLM-серверу, Yandex/DataForSEO ключи — всё это для контент-конвейера
и SEO-автоматизации, не для основной функциональности каталога/ЛК/заказов. Если новая фича не
касается генерации контента или ключевиков — эти интеграции можно игнорировать.
