# Дубли брендов: откуда берутся и как склеивать

## Инцидент iseymordc (04–06.10.2026)

Опубликованный `iseymordc` (2804, из лид-импорта) → владелец с Яндекса на карточке жмёт «Я владелец бренда»
→ `/brand-claim/2804` (ROLE_USER) → 302 на /login → на логине единственная ссылка на регистрацию —
«Вы бренд? Зарегистрировать бренд» (`register?brand=1`) → форма **всегда создаёт новый Brand** + триал
(`RegisterController.php:74-98`, слаг `-1` из `generateUniqueSlug` :185) → `LoginSuccessHandler` возвращает
на `/brand-claim/2804` → заявка. Итог: дубль 3681 + две триал-подписки. Тот же путь в тот же день прошёл
посетитель `netoclothes` — это системный дефект флоу, не ошибка пользователя.

Постфактум-детектор есть: `ModerateTickCommand::duplicateFlags` (:697, Jaccard ≥0.70 + домен) пометил 3681
`duplicate_candidate`, но бренд и триал к тому моменту уже созданы.

## Склейка (ранбук)

```
php bin/console app:brand:merge <dup> <survivor> --dry-run   # смотреть колонку «Пропущено»
php bin/console app:brand:merge <dup> <survivor>
```
Переносит товары, команду, заказы, юрлица, инвайты, заявки, интент-клики; действующая подписка дубля
не переносится, если у survivor есть своя (#270). SEO/RAG-артефакты остаются на дубле; дубль soft-delete +
`merged_into` → 301. Подписка дубля остаётся trial на удалённом бренде — проверить, что напоминания об
окончании триала не шлются по удалённым брендам.

## План профилактики (по приоритету)

1. **Регистрация из флоу заявки не создаёт бренд** — ✅ сделано (feat/brand-signup-dedupe, `ClaimFlowDetector`; PR в описании ветки) (~40 строк + тест). На /login при target_path
   `/brand-claim/{id}` — «Создайте аккаунт, чтобы подтвердить владение «X»» → обычная `/register`;
   `RegisterController` при таком target_path игнорирует `?brand=1`. Бренд-роли выдаёт одобрение заявки
   (`BrandClaimService.php:134-142`).
2. **Гард точного совпадения при создании бренда** — ✅ сделано (`BrandRepository::findLiveExactDuplicate`, чекбокс `notDuplicate`, строка «⚠️ возможный дубль» в TG) (~60–80 строк). Нормализованное имя / `slug(title)` против
   живых брендов (`status != deleted`, `merged_into IS NULL`) → блок «Бренд уже в каталоге — заберите
   карточку» + чекбокс «Это другой бренд»; при чекбоксе — создать и добавить в TG-уведомление
   «⚠️ возможный дубль» с командой склейки. Только точное совпадение: короткие общие имена гасит чекбокс.
3. **Мелочи:** ✅ `duplicateFlags` исключает собственный slug (title- и domain-проверка).
4. **Отложено:** live-поиск по каталогу при вводе названия — нет поискового эндпоинта, саморегов пока ~7.
