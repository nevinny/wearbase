# Флоу конвейера: рекламное описание бренда

Как из бренда рождается рекламное описание (`brand.description`) — заземлённое на реальных
фактах, а не выдуманное моделью.

## Коротко

Собираем **реальные факты бренда** из сети (сайт, маркетплейсы, упоминания) → складываем в
векторную базу → описание пишется **по этим фактам** (не из головы модели), с вплетёнными
поисковыми фразами → прогон через фильтры качества → публикация на прод → замер в Google и
автоперегенерация слабых.

## Плюсы (за что зацепиться)

- **Заземление на фактах, ноль галлюцинаций.** Описание — пересказ реально добытого о бренде,
  а не выдумка. Мало фактов → бренд не получает «воду», а ждёт дозревания корпуса.
- **Тройной гейт качества.** Отсекаем: AI-почерк/переспам/воду (методика SpamBrain/Human-likeness),
  отказы модели (факты не о том бренде → ручная проверка), дубли с другими брендами.
- **SEO встроено.** Реальные поисковые фразы из Wordstat вплетаются в текст и title — описание
  сразу заточено под спрос.
- **Без риска для работающего.** Контент версионируется (безопасный откат), опубликованное не
  перетирается; новая версия промоутится только после гейтов.
- **Замкнутый цикл с Google.** Меряем показы в GSC, проигравшие страницы автоматически
  перегенерируем, работающие не трогаем.
- **Полностью автономно и локально.** Весь AI-стек на своём сервере (без оплаты внешних API за
  генерацию), конвейер сам себя гонит и переживает перезапуски.

## Детально (внутрянка)

Полный технический reference конвейера — [rag_pipeline.md](rag_pipeline.md). Здесь — путь именно
рекламного описания.

### Магистраль: довести бренд до фактов

```
discover → crawl → fetch → embed → generate → (push на прод)
   net      net     net     gpu       gpu         net
```

1. **discover** (`app:brand:discover`) — ищет URL-кандидаты (свой сайт, маркетплейсы, упоминания)
   через Yandex Search API + SearXNG → очередь `brand_source_url`. Контент не качает.
2. **crawl** (`app:brand:crawl`) — разворачивает own_site: sitemap + ссылки → внутренние страницы
   (`own_page`, `product_sample`).
3. **fetch** (`app:brand:fetch`) — качает чистый текст (trafilatura) → `brand_source_document`.
   Дренаж URL завершён → `status=scraped`.
4. **embed** (`app:brand:embed`) — чанки (`TextChunker`) → эмбеддинги (ollama `qwen3-embedding`,
   1024-dim) → Qdrant (`brand_chunks`). `status=embedded`. Теперь у бренда есть векторная база
   его реальных фактов.

### Generate (`app:brand:generate-content`)

5. **Выбор** — `findWithoutDescription` (без описания; в `--grounded-only` исключаются
   `deferred`/`review`, чтобы не крутиться на отказниках).
6. **RAG-retrieve** (`BrandRagService::retrieve`) — факты из Qdrant: ≤8 чанков → один запрос;
   >8 → 5 граней (ассортимент / материалы / философия / аудитория / производство), дедуп, срез
   топ-8. **Gate**: `чанков ≥ 3` И `cosine ≥ 0.5`. Не прошёл → `context=null`.
7. **Развилка:** gate не пройден + `--grounded-only` → **`deferred`** (тонкий корпус, описание не
   пишем). Пройден → генерим на фактах.
8. **Ключевики** — топ-фразы Wordstat (`brand_keyword`) вплетаются в текст, title из топ-фразы.
9. **Генерация** (`LlmService::generateBrandDescription`, gemma4:26b) — строго на переданных
   фактах (`facts=context`) + ключевики.
10. **Три гейта** (иначе не сохраняем):
    - **refusal** (`ContentValidator::isRefusal`) — «факты не о бренде» → `review` (ручная
      верификация, не публикуем, не ретраим);
    - **QA-гейт** (`ArticleQaService`) — AI-почерк/переспам/вода: SpamBrain ≥7 И Human-likeness ≥8
      И overall ≥75;
    - **near-duplicate** — Jaccard ≥0.85 с другими брендами → `review`.
11. **Сохранение** → `brand.description` + meta + `anons`. `status=done`. Версионирование
    (`BrandContentVersioner`: baseline до + новая активная ревизия после). `markContentChanged`.

### Доставка и обратная связь

12. **push** (`app:brand:push`) — на прод (агент-API + HMAC), если `isPublishReady`:
    `description + meta + status=done + faq∈{done,skipped} + keywords∈{found,not_found}`.
13. **Closed-loop** — GSC меряет показы; `loss` → форс-регенерация, `win/neutral` → оставить,
    `not_indexed` → индексационные рычаги.

**Суть:** описание = пересказ реально добытых фактов бренда (RAG из Qdrant), с поисковыми фразами,
отфильтрованный тремя гейтами. Мало фактов → `deferred` (ждёт, не пишем воду); чужие факты →
`review` (ручная проверка).
