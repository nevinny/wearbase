# Прод-стек раздела `/demo/` — что чем делаем

> Решения по инструментам для лендинга-портфолио и демо-одностраничников.
> Концепция — [demo_landing_concept.md](demo_landing_concept.md), дизайн-система — [demo_design_system.md](demo_design_system.md).
> Всё проверено на этой машине и на прод-хостинге, цифры ниже — замеры, не оценки.

## 1. Референсы идей

`godly.website` (композиция и ритм), `21st.dev` (структура компонентов на Tailwind),
`60fps.design` (движение и тайминги), `cta.gallery` (блоки призыва), `land-book`/`siteinspire`,
`glass3d.dev` (стеклянные эффекты — точечно). Прописаны в `.claude/agents/art-director.md`,
арт-директор обязан называть в ответе, что именно откуда взял.

## 2. Генерация картинок — Freepik, но с жёсткой границей

- **Можно:** собственная графика раздела `/demo/` — фоны, текстуры, абстрактные обложки пустых
  клеток («Место свободно — ваш бренд?»), иллюстрации к блокам «что входит» и FAQ.
- **⛔ Нельзя:** генерить что-либо для демо конкретного бренда. Демо продаёт мысль «это про нас,
  это наши вещи»; сгенерированная «их» футболка — подделка товара, которого нет, и мгновенная потеря
  доверия, если владелец заметит. На страницах брендов — **только их собственные фото** из открытых
  каналов (правила использования — `demo_landing_concept.md` §2).
- Лицензия: коммерческое использование сгенерированного на Freepik требует платного тарифа —
  проверить перед публикацией.

## 3. Картинки — AVIF, но не для скролл-секвенций

**Статика — AVIF, это большой выигрыш (замер на реальном кадре Splash!):**

| Формат | Вес одного кадра | Экономия |
|---|---|---|
| исходный JPEG (после `sips -Z 1200`, q80) | 200 522 Б | — |
| `sips -s format avif` (без тюнинга) | 112 234 Б | 44 % |
| **`avifenc -q 60 -s 6`** | **42 463 Б** | **79 %** |
| `avifenc -q 70 -s 6` | 56 637 Б | 72 % |

Рабочая настройка — **`avifenc -q 60 -s 6`** (`/opt/homebrew/bin/avifenc`, стоит). Для Splash!
это 4 МБ страницы → около 0,9 МБ.

Обязательная обвязка:
- `<picture><source type="image/avif" srcset="…"><img src="…jpg" …></picture>` — Safari младше 16
  и старые Android AVIF не понимают, JPEG остаётся как запасной;
- в `public_html/.htaccess` добавить `AddType image/avif .avif` — иначе Apache отдаст файл
  с `application/octet-stream` и браузер его не покажет (в текущем `.htaccess` объявления нет);
- ширина и высота у `<img>` проставлены, `loading="lazy"` ниже первого экрана.

**⛔ Чего AVIF не умеет и почему «видео-скролл на AVIF» не делаем:** анимированный AVIF
проигрывается браузером сам, **перемотать его по кадрам из JS нельзя** — скролл-скраб на нём
не собрать в принципе. Вариант «много отдельных .avif-кадров и подмена по скроллу» технически
возможен, но декодирование AVIF дороже JPEG, и на телефоне это даёт рывки ровно там, где нужна
плавность. Вывод: **движение делаем трансформациями (transform/opacity) по реальным фото**,
а AVIF используем как формат статики. Это и легче, и надёжнее, чем секвенция.

## 4. Анимации — anime.js v4 с CDN

- Подключение: `https://cdn.jsdelivr.net/npm/animejs@4.3.0/dist/bundles/anime.umd.min.js`
  (проверено, 200, 108 КБ; на cdnjs тот же файл — запасной адрес).
- В v4 **встроен `onScroll()`** (ScrollObserver) — отдельная библиотека под скролл-триггеры не нужна:
  ```js
  animate('.card', {
    y: [40, 0], opacity: [0, 1], ease: 'out(3)',
    autoplay: onScroll({ enter: 'max-=100 top', leave: 'min+=100 bottom', sync: 0.5 })
  });
  ```
  `sync` включает привязку прогресса к скроллу, без него — обычный триггер входа в экран.
- Актуальную документацию тянуть через **context7** (`/juliangarnier/anime`), а не по памяти:
  API v4 несовместим с v3 (`anime.timeline()` → `createTimeline()`).
- Обязательно уважать `prefers-reduced-motion: reduce` — при нём анимации выключаются, контент
  показывается сразу.
- Бюджет движения: 2–3 приёма на страницу. Демо продаёт бренд, а не наши эффекты.
