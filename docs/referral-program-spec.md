## 1. Дизайн наград

Валюта с реальной маржой и встроенными лимитами — **AI-подсказки гардероба**.

| # | Награда | Стоимость | Риск | Вердикт |
|---|---|---|---|---|
| A | **Бамп AI-квоты** | LLM-токены; общий предохранитель `WardrobeAiMeter` остаётся | Фродовые аккаунты (гасится §3) | ✅ база |
| B | Премиум-фичи | Consumer-premium строить с нуля (есть только брендовые тарифы) | Отложенный продукт ради канала | ⏸ после premium |
| C | Косметические бейджи-тиры | ~0 (паттерн `engagement.earned`) | Слабый мотиватор сам по себе | ✅ слой поверх A |
| D | Скидки/баллы заказов | Прямые деньги + учёт лояльности | Вне продукта | ❌ |

**Рекомендация A+C**:
- Приглашённому (welcome): `+10 AI-подсказок/день` сверх базы 30 на 30 дней + бейдж «По совету подруги».
- Приглашающей (за каждого квалифицированного): `+5/день` на 14 дней; бейджи-тиры на 3/10 друзей (пороги бейджей ≠ множители выплаты).
- Числа — константы сущности-награды, не хардкод. База 30/день и глобальный потолок инсталляции не меняются; бамп живёт строго между ними.

## 2. Капы и тиры

1. Кап на пару (inviter, invitee) = 1 — гарантирован `uniq_referral_once` + идемпотентность ledger'а.
2. **Квалификация**: подтверждён email И ≥1 вещь/образ за 30 дней. Оплата голой регистрации = корм для фермы.
3. Месячный кап: оплачиваются первые **5 квалификаций/календарный месяц**; далее счётчик растёт, грант нет. Тиры — только пороги бейджей.
4. Гранты истекают (`expires_at`), неиспользованные дни не переносятся. Ledger append-only, `revoked_at` — админ-операция.
5. Потолок бонуса: ≤ **+30/день** на пользователя (эффективный лимит ≤60 даже при 20 друзьях).

## 3. Антифрод

| Механизм | Решение |
|---|---|
| Самоприглашение | Закрыто в `LookShareReferralService:47–50`; дубль-guard на слое grant'а |
| Managed-аккаунты | `isManaged()` не может быть источником награды — дети создаются бесплатно, готовый канал накрутки |
| Одноразовые домены | Статический список ~100 доменов (`DisposableEmailDomains`); проверка на этапе квалификации, не блокирует регистрацию |
| Дубли устройств | Новые данные не собираем (политика минимизации). Вместо этого: velocity-лимит `referral_register` 5/hour per IP рядом с существующим `native_auth_login`; кластер-флаг ≥K приглашённых без единого действия. Автоблокировки нет — только флаг |
| Очередь ручной проверки | Триггеры: ≥8 событий/24ч ИЛИ ≥3 флагов ИЛИ ожидаемая выплата >150 подсказок/мес → гранты в `status='review'`. Разбор: секция EasyAdmin + пуш в TG через `AdminNotifier::send()` |

Принцип: фрод-контроль на слое **наград**, не атрибуции. `referral_event` остаётся честным фактом; экономика решает, платить ли.

## 4. Дашборд приглашающей в ЛК

Блок «Приглашай подруг» в `templates/account/dashboard.html.twig` после сетки статистики, только ROLE_CUSTOMER:
1. Персональная ссылка (readonly-input + копирование, паттерн `outfits.html.twig:50–53`).
2. «Подруг приглашено: N» — COUNT по `referral_event`.
3. «Бонус: +X подсказок/день до DD.MM» — сумма активных грантов.
4. Прогресс к следующему тиру.

**Переиспользуем look-share токены; отдельный код не вводим**: funnel `?ref={shareToken}` уже проложен end-to-end, второй механизм удвоил бы поверхность атрибуции и фрода. Vanity-код (`/i/masha`) — осознанно отложен; шов: колонка `code` в будущей `referral_program_code`.

## 5. Шов для кружков подруг

- `referral_event` = рёбра графа «кто кого привёл»; `source VARCHAR(32)` расширяем новыми каналами без миграции схемы.
- Правило: **не денормализовать граф** — кружкообразование читает пары напрямую.
- `referral_reward_ledger.referral_event_id` связывает доверие с формированием круга («подруги Маши» = приглашённые Маши + взаимные 2-го уровня).
- Внутрисемейные рёбра исключаются из кандидатов кружка через `$familyRole`.
- Единственное требование к текущей реализации: не создавать сущностей, скрывающих пару (inviter, invitee).

## 6. Ledger наград

```sql
CREATE TABLE referral_reward_ledger (
    id INT AUTO_INCREMENT PRIMARY KEY,
    user_id INT NOT NULL,
    role ENUM('inviter','invitee') NOT NULL,
    kind VARCHAR(32) NOT NULL,               -- 'ai_quota_bump' | 'badge'
    amount INT NOT NULL DEFAULT 0,
    idempotency_key VARCHAR(80) NOT NULL,    -- ref:{eventId}:inviter:bump и т.п.
    referral_event_id INT NULL,
    reason VARCHAR(64) NOT NULL,
    status VARCHAR(16) NOT NULL DEFAULT 'active',   -- active|review|expired|revoked
    granted_at DATETIME NOT NULL,
    expires_at DATETIME NULL,
    UNIQUE KEY uniq_reward_idem (idempotency_key)
) DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
```

Идемпотентность через детерминированный `idempotency_key`: повторный grant — no-op, сбой между flush'ами безопасен.

Компоненты:
- `ReferralRewardGrant` (по образцу `ReferralEvent`), репозиторий с `findActiveByUser/sumActiveDailyBump/existsByIdempotencyKey`
- `ReferralRewardService::grantOnQualified()` — транзакция: квалификация → два insert'а
- `WardrobeAiAllowance` — клон паттерна `WardrobeAiMeter` (per-user день/used); эффективный лимит = 30 + Σ активных грантов; контроллеры переключаются с raw-limiter на allowance; config-limiter остаётся антиспам-полом
- Milestone-бейджи: ленивый пересчёт на дашборде, запись при первом достижении порога
- `app:referral:expire-grants` — cron-команда истечения
