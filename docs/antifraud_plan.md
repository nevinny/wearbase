## Где уже защищён (сильно)

**Деньги — узкое горлышко, и оно крепкое.** Чтобы мошенник *получил* оплату, нужен
`SellerLegalEntity` + платёжный счёт с боевыми кредами шлюза
(`SellerPaymentAccount::isReadyToAcceptOnline()` требует `status=active` + `account_ref`
+ непустой секрет). KYC юрлица делает сам шлюз (YooKassa). Деньги идут напрямую бренду,
через площадку не проходят → лицензия платёжного агента не нужна, и **финансовый фрод
ограничен по построению**.

**Регресс к бренду** (оферта продавца v1.1.0, миграция `Version20260613_seller_offer_v1_1_recourse`,
задеплоено 2026-06-13): если площадка как владелец агрегатора вернула покупателю предоплату
(ст. 12 ЗоЗПП) — бренд возмещает в 5 р.д.; все расходы по возвратам/претензиям — на бренде.

**Прочее, что работает:** краудсорс-валидация data-point'ов (✗-голоса авто-скрывают),
soft-delete + `unpublish` через агент-API, дрип-публикация (бренды не мгновенно публичны),
Turnstile на регистрации, `brandHasOtherOwner()` (предупреждение о второй заявке).

## Где дыра — репутационная (сценарий владельца)

Фейковые товары не требуют денег — достаточно опубликовать листинги. Два открытых места:

1. **Авто-грант claim'а ВКЛючён** — `BRAND_CLAIM_AUTOGRANT_EMAIL=1`, `BRAND_CLAIM_AUTOGRANT_VK=1`
   (и локально, и на проде, `.env:70-71`). Любой, кто докажет контроль над email бренда
   или админство VK-группы, **мгновенно получает владение без ревью человеком**. Риск
   перехвата брошенных брендов с устаревшим enrichment-email.
2. **Публикация товара — без модерации.** `BrandProductController::publish` — владелец сам
   жмёт `draft↔active`, товар сразу публичный. Никакого ревью.

## Что добавить — по убыванию отдачи

### 1. Выключить авто-грант claim'а  ⚡ (1 строка env, обратимо)
`BRAND_CLAIM_AUTOGRANT_EMAIL=0`, `BRAND_CLAIM_AUTOGRANT_VK=0` → каждый claim идёт через
`BrandClaimAdminController` на подтверждение владельцем. Email/VK-доказательство остаётся,
но владение выдаёт человек. Максимум защиты за минимум усилий.
**Минус:** ручная обработка заявок (на текущем объёме ок).

### 2. Модерация первой публикации для новых/непроверенных
Товары нового бренда → очередь ревью (`Product` статус `pending`/`draft`), публикуются после
проверки; у проверенных продавцов с историей — автопубликация. Переиспользовать статусы
Product (`draft/active/archived`) + админ-ревью (инфраструктура `RagDashboardController` есть).
Привязать к «тиру доверия» бренда. Прямо закрывает «фейк сразу в выдаче».

### 3. Тиры доверия + бейдж «Проверенный продавец»
- Tier 0 unclaimed (RAG-данные) — read-only, краудсорс-валидация.
- Tier 1 claimed (email/VK) — может редактировать, лимиты.
- Tier 2 verified seller (подтверждённое `SellerLegalEntity` + платёжный счёт) — может
  продавать, бейдж «Проверенный продавец» покупателю.
Продажу (приём денег) пускать только с Tier 2; непроверенные = только витрина.
Делает KYC-чекпойнт видимым сигналом доверия и преимуществом для покупателя.

### 4. Велосити / дубль-чек
Лимит товаров/день для новых продавцов; переиспользовать `NearDuplicateDetector` для отлова
массовых AI-листингов; базовая валидация картинок (в `_seo` есть `photo_verify.py` как образец).

### 5. Kill switch + контрафакт
Быстрое «скрыть бренд + все его товары» (soft-delete уже есть — оформить одной операцией);
в оферте 1.1.0 уже есть гарантии прав на товар/контент (клауза 5) — добавить процедуру
takedown контрафакта/имперсонации.
