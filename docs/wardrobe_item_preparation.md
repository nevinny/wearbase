# Подготовка вещей для AI-стилиста: первая версия

Дата: 2026-09-13. Реализация основана на `main` (`b9b65f3`).

## Что работает

- Распознавание возвращает `colorName`, `materialText` и `season` отдельно от заметок.
  Цвет ограничен 100 символами, состав — 2000; некорректные типы превращаются в null.
- Сезон соответствует форме: `all`, `spring`, `summer`, `autumn`, `winter`.
  Неоднозначный «демисезон» остаётся неизвестным. Состав запрашивается только с читаемой бирки;
  это инструкция модели, поэтому предложенное значение всё равно требует проверки человеком.
- Очередь сохраняет поля в `WardrobeItemDraft.attributes`, затем они доступны для правки
  и переносятся в существующие поля `WardrobeItem`. Фасон пока остаётся в заметках.
- Модель, версия схемы и общая уверенность сохраняются в минимальной диагностике `ai_raw`.
  Ключ кеша учитывает схему, модель, провайдера и содержимое фото; прежний кеш не используется.
- Пустая строка или явный null при подтверждении очищает неверную подсказку.
  Повтор принятия возвращает прежнюю вещь без изменения подтверждённых полей.
- Массовое подтверждение в браузере отправляет текущие значения полей каждой уверенной
  карточки. Карточки с ошибками остаются на странице вместе с ручными правками.
  Уровни `med` и `low` требуют индивидуального подтверждения.
- Ошибку распознавания можно исправить ручным вводом. `processing` учитывается как
  незавершённая работа и не показывается как готовая карточка.

## Существующие вещи

В гардеробе появилась ссылка «Подготовить вещи» → `/account/wardrobe/preparation`.
Список показывает активные носимые вещи с пропусками категории, цвета или сезона,
по 30 записей с продолжением; семейный доступ сохраняется через `member`.

Открыть «Проверить карточку» → разрешить обработку фото → «AI-подсказки по фото».
Пустые поля формы заполняются, отличающиеся значения предлагаются с отдельными флажками.
Выбрать нужные изменения и сохранить карточку. Без сохранения данные вещи в БД не меняются.
Категория сопоставляется с названием в существующем select; неизвестная категория
автоматически не создаётся. Новое распознавание фото не создаёт вторую вещь.

Эта версия обогащает существующие вещи через их форму по одной. Фоновое массовое
обогащение существующего гардероба теперь доступно небольшими пачками командой ниже.
Отдельные структурированные фасон/стили,
уверенность каждого поля, удаление фона и поиск визуальных дублей — следующие этапы.
Факт готовности к подбору не заменяет проверку текущей доступности вещи.

## Фоновое обогащение существующих вещей

Команда намеренно требует email владельца и не перебирает всю базу автоматически:

```bash
php bin/console app:wardrobe:prepare-existing-items \
  --user=user@example.com --limit=15 --dry-run

php bin/console app:wardrobe:prepare-existing-items \
  --user=user@example.com --limit=15
```

`--dry-run` показывает кандидатов, `--limit` ограничивает одну пачку, а `--after=ID`
продолжает обработку после конкретной вещи. Если фото отсутствует или AI не ответил,
вещь пропускается и остаётся в списке подготовки. Параллельный запуск получает lock и
завершается без обработки. Команда дополняет только пустые категорию, цвет, состав и
сезон; ручные и ранее подтверждённые значения не перезаписываются.

Перед запуском на production нужен применённый `Version20260913_wardrobe_draft_attributes`;
сама команда не изменяет черновики и не требует Qdrant.

## Установка и проверки

До запуска обновлённого приложения и worker применить миграцию
`Version20260913_wardrobe_draft_attributes`: добавляет nullable JSON `attributes`.
Существующие черновики совместимы: отсутствие новых атрибутов означает пустые поля;
исторические заметки автоматически не разбираются. Работать с production-БД в этой задаче не требовалось.

Проверки:

```bash
php vendor/bin/phpunit tests/Controller/WardrobeControllerTest.php tests/Controller/WardrobeIngestControllerTest.php tests/Controller/WardrobePreparationControllerTest.php tests/Repository/WardrobeItemDraftRepositoryTest.php tests/Service/Wardrobe/WardrobeAiServiceTest.php tests/Service/Wardrobe/WardrobeOutfitServiceTest.php tests/Command/IngestWardrobeDraftsActivationTest.php tests/Command/CleanupWardrobeDraftsCommandTest.php
php vendor/bin/phpunit tests/Command/PrepareExistingItemsCommandTest.php
node --test tests/browser/wardrobe-item-preparation.test.cjs
APP_ENV=test php bin/console lint:container
APP_ENV=test php bin/console lint:twig templates/account/wardrobe
```

Браузерные тесты требуют установленных зависимостей `package.json` и Chromium Playwright.
Они выполняют реальные скрипты шаблонов, подменяя HTTP, без вызовов AI.
PHP-интеграция использует одноразовую SQLite-БД. Живой vision-пилот на LLM-риге,
качество распознавания и production-миграция не проверялись этой серией тестов.
