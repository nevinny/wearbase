# 4× Tesla V100 SXM2 + NVLink — выводы из видео-обзора (2026-09-24)

Источник: расшифровка русскоязычного YouTube-обзора (`v100-nvlink-transcript.txt` в корне репо, не закоммичен).
Автор 3,5 недели собирал и тестировал самодельный «DGX»: 4× V100 SXM2 16 ГБ на китайской
плате с NVLink, водянка; сравнивал с арендованными 4× V100 32 ГБ (с NVLink и без, через PCIe) и 2× RTX 3090.
68 конфигураций, 13 LLM, 8 моделей для картинок, 2 для видео.

**Главный вывод:** лишние карты дают не скорость, а **память под KV-кэш/контекст**. 2→4 карты:
+34 % ток/с, но контекст 26K → 440K (×17). Для LLM от 14B+ сборка за ~180 тыс. ₽ лучше пары 3090;
для генерации видео проигрывает в 4–5 раз, для картинок — ничья (кроме Qwen-Image).

## Цифры

| Что | Результат |
|---|---|
| Gemma 3 12B Q4 GGUF, 4 карты: LM Studio / llama.cpp / vLLM (форк под Volta, TP) | 63 / 66 / **107** ток/с |
| Конвейерный режим (pipeline, llama.cpp) vs тензорный (TP, vLLM) | 32 vs 70 ток/с (~×2) |
| Плотная 27B: 1 карта 16 ГБ / 2 карты TP / 4 карты TP | OOM / 52 ток/с, 26K ctx / 70 ток/с, 440K ctx |
| 14B: 1 → 4 карты | 63 → 116 ток/с; контекст 22K → 273K |
| MoE 35B (~3B активных) | 115 ток/с — быстрее плотной 27B; KV-кэш 710K (TP) / 1,2M (гибрид 2×2) |
| 4 параллельных запроса | ~200 → ~700 ток/с суммарно (почти линейно, decode упирается в чтение весов) |
| Без NVLink (PCIe) | −10 % на 1 карте, −12 % на 2, **−25 % на 4**; TP/pipeline-разрыв сжимается с ×2 до ×1,5 |

| 8 из 10 моделей на 2× 3090 (48 ГБ) | упёрлись в свой обученный контекст (262K), а не в память |

## Грабли, полезные вне этого железа

1. **Open WebUI по умолчанию режет прикреплённый файл на чанки и отдаёт модели 3–4 фрагмента** (RAG),
   а не весь текст. Для длинного контекста включить «обход встраивания и извлечения»; проверять
   по заполнению KV-кэша в логе сервера, а не на глаз.
2. **Скорость ничего не значит, пока не прочитан ответ**: Qwen 3.8 4-bit на 2 картах TP выдавал
   зацикленный мусор (паддинг размерности слоя 4120→4128 проверен авторами только для TP=4);
   повторилось на двух независимых стендах.
3. **Бэкенд внимания в vLLM выбирается перебором**: из 4 один падает, один не работает, 75 vs 107 ток/с у оставшихся.
4. **Нет BF16 у Volta** → модели, обученные на BF16 (Qwen-Image), переполняются в FP16 → «чёрный квадрат»
   без ошибок в логах. Лечится эмуляцией BF16 (×3 медленнее). Проверять латенты до VAE.
5. **Квантованный text-encoder/коннектор в LTX** → модель игнорирует промпт (рисует «рыцаря» на любой запрос).
   Опасно сжимать именно мост «текст→латент», а не языковой блок целиком.
6. **Один процесс ComfyUI держит ~21 ГБ копии весов в системной RAM**; 4 экземпляра → 80 ГБ.
   Лечится флагом, запрещающим офлоад (веса живут только в VRAM).
7. Одну картинку/кадр несколько карт не ускоряют (последовательные шаги); выигрыш — только
   N независимых экземпляров = пропускная способность.
8. «Если чего-то нет, подожди»: 20 часов патчей форка vLLM, а через неделю вышла версия с исправлениями.
9. Перед покупкой железа арендовать ту же конфигурацию на пару часов (посекундная тарификация, ~1000 ₽).

## Применимость к нашему ригу (см. [llm_infra_handoff.md](llm_infra_handoff.md))

- Наш стек (ollama = llama.cpp) при дроблении модели работает **только в pipeline-режиме** — это
  подтверждает замер из §2.1 handoff: сплит по 5 картам ~13 ток/с против 35–40 на одной A4000.
  Плюс у нас PCIe Gen1 x1 (~250 МБ/с) против NVLink 300 ГБ/с в видео — TP нам бессмыслен
  и через vLLM, а обмен между картами — узкое место.
- Прямой вывод для генерации контента: **MoE-модели с ~3B активных параметров быстрее плотных
  26–27B при сопоставимом размере**. `gemma4:26b` (наш победитель в [model-ab-bench.md](model-ab-bench.md)) —
  при выборе замены смотреть на MoE, влезающие в одну A4000.
- **Параллельные запросы почти бесплатны** (decode ограничен чтением весов) — батчевый
  `generate-content` выгоднее гнать с `OLLAMA_NUM_PARALLEL` > 1, если хватает VRAM под кэш. Не
  проверено на нашем риге — замерить перед включением.
- Видео-ген локально: подтверждается вывод памяти про Seedance/Wan — нужен
  Ampere+ (BF16), и даже тогда критична системная RAM (энкодер LTX ~29 ГБ RAM). У нас 7,6 ГБ — не вариант.
- Если когда-то апгрейдить риг под LLM: 4× V100 SXM2 16 ГБ + NVLink-плата ≈ 180 тыс. ₽ (цены 09.2026:
  модуль 16 ГБ ~12–14,5 тыс. ₽, 32 ГБ ~60–80 тыс. ₽, плата на 4 карты ~72 тыс. ₽ с пошлиной).
  Но потребуется другой хост: плате нужен CPU/RAM (ComfyUI, офлоад), 200 Вт в простое, 1,35 кВт в пике,
  низкая ликвидность и неделями возни. Модули SXM2 не проверить без платы — брать только у продавцов с проверкой.
