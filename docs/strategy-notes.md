# WEARBASE — Стратегические заметки

## Модель монетизации (Costco-подход)

### Суть
Бренды платят **фиксированную подписку** за присутствие в каталоге.  
WEARBASE **не берёт % с продаж** — это ключевое отличие от маркетплейсов.

### Структура
```
Бренды платят подписку → финансируют платформу
Стилисты заходят бесплатно → создают ценность для брендов (трафик)
```

### Почему сработает
- Брендам психологически проще заплатить 3 000 ₽/мес, чем отдать 30% с оборота
- Нет конфликта интересов: платформе выгодно привлекать стилистов, а не накручивать комиссию
- Предсказуемый MRR, независимо от продаж

### Тарифная сетка (реализована)

| Тариф | Цена | Фичи |
|-------|------|------|
| **Free** (30 дней) | 0 ₽ | Карточка бренда, до 10 товаров, 5 изображений |
| **Basic** | 1 500 ₽/мес | До 50 товаров, 20 изображений, приоритет в выдаче |
| **Premium** | 3 000 ₽/мес | Безлимит товаров и изображений, аналитика, приоритет |

Сущности: `Tariff`, `Subscription`, `Payment` — созданы, мигрированы, засеяны.

### Целевые метрики
- Конверсия outreach → регистрация: 30%+ (из 130 брендов)
- Конверсия free → paid: 30-40%
- Цель: 40 платных брендов → ~120 000 ₽/мес MRR
- Точка безубыточности: 30-40 платных брендов

### Риски
- Курица и яйцо: бренды не придут без стилистов, стилисты без брендов
- Решение на старте: ручной outreach по 130 брендам из списка

## SEO-стратегия

### Три уровня запросов

```
1. Брендовые (самые горячие, быстрый выигрыш)
   «[название бренда] официальный сайт»
   «[бренд] где купить»
   «[бренд] интернет-магазин»
   → У брендов без сайта — нет конкурента в выдаче. Ты занимаешь это место.

2. Категорийные (средний срок)
   «российские бренды женской одежды»
   «купить платье у производителя»
   «одежда без маркетплейса»

3. Информационные (длинный хвост, сейчас горячо)
   «альтернативы Wildberries для покупателей»
   «где покупать одежду если ушёл с WB»
   «российские дизайнеры одежды список»
```

### Быстрый выигрыш — брендовые запросы
- Из 129 брендов без сайта — многие уже ищут по названию
- Конкурентов в органике нет
- Одна хорошая страница бренда на WEARBASE = топ по брендовому запросу за 2-4 недели

### Временной горизонт
- SEO — 6-12 месяцев до устойчивого результата
- Первые органические посетители от брендовых запросов — через 2-4 недели

## LLM-видимость

### Текущий тренд
ChatGPT, Claude, Perplexity всё чаще используются как «посоветуй где купить».
Нейронки скрейпят **структурированные страницы с описанием бренда** — не WB/Ozon.

### Что нужно для индексации нейронками
- Чёткая структура страницы бренда: кто, что, ценовой сегмент, стиль, контакты
- schema.org разметка ✅
- Упоминания на других ресурсах (co-citation) — даже небольших
- Простой читаемый текст без SEO-спама

### Риск
Нейронный поиск убивает классические SEO-сниппеты. Пользователь спрашивает Claude — и не кликает на сайты вообще. Нужно оптимизироваться под LLM-видимость как отдельный канал.

- Стилисты заходят бесплатно (упрощённая верификация)
- Они создают подборки → привлекают покупателей → ради этого бренды платят
- Модерация стилистов: нужна или нет? Качество ассортимента зависит от тех, кто подбирает вещи

## Архитектура: ключевые решения

### Уведомления
- `NotificationDispatcher` — центральный сервис диспетчеризации
  - **In-app**: создаёт запись `Notification`, сохраняется в БД
  - **Email**: через `EmailNotifier` (Symfony Mailer, TemplatedEmail)
  - **Telegram**: через `TelegramNotifier` (Bot API, `sendMessage`)
  - Каналы управляются через `NotificationSettings` (per-user, per-event-type)
- Типы событий: `order_new`, `order_status_changed`, `order_shipped`, `order_delivered`, `brand_invite`, `product_low_stock`, `weekly_stats`

### Платежи (ЮKassa)
- `PaymentService` — обёртка над YooKassa SDK
  - `createSubscriptionPayment()` — платёж за подписку бренда
  - `createOrderPayment()` — оплата заказа покупателем
  - `handleNotification()` — вебхук (меняет статус подписки/заказа)
- Webhook endpoint: `POST /payment/yookassa/webhook` (public)
- Требует: `YOOKASSA_SHOP_ID`, `YOOKASSA_SECRET_KEY` в `.env.local`

### Переводы
- `ProductTranslation`, `BrandTranslation` — сущности (один Product → много локалей)
- `TranslationExtension` (Twig) — `brand_t()`, `product_t()` для рендеринга
- UI в ЛК бренда: `/brand/products/{id}/translations`

### SEO
- `noindex, follow` на страницах фильтров (letter, city, style, search, brand, page > 1)
- `ItemList` schema только на page 1 (чтобы не перегружать Google)
- FAQPage schema на карточке бренда (для rich-сниппетов)

### Посадочные страницы (landing pages)
- **`/ru/without-marketplaces`** — для брендов, уходящих с Wildberries/Ozon. УТП: «0% комиссии, фиксированная подписка». Сравнение маркетплейсы vs WEARBASE, тарифы, соцдок (бренды), форма email.
- **`/ru/for-brands`** — общая страница размещения бренда. 4 шага, форма регистрации.
- Сбор лидов: `LandingLead` (email, source, created_at). POST `/landing/lead`, CSRF.
- В sitemap.xml (priority 0.8), index/follow, canonical, og.
- Целевые запросы: «альтернатива маркетплейсам», «продавать без комиссии», «уйти с вайлдберриз», «разместить бренд одежды»

## Настройка перед запуском

### Переменные окружения (`.env.local`)
```env
MAILER_DSN=smtp://...
YOOKASSA_SHOP_ID=
YOOKASSA_SECRET_KEY=
TELEGRAM_BOT_TOKEN=
CDEK_ACCOUNT=           # Интеграционный аккаунт CDEK
CDEK_PASSWORD=          # Пароль к API CDEK
BOXBERRY_TOKEN=         # API-токен Boxberry
```

### Вебхуки (настроить в панелях)
- ЮKassa: `https://wearbase.ru/payment/yookassa/webhook`
- Telegram: `https://wearbase.ru/telegram/webhook` (установить через `TelegramNotifier::setWebhook()`)

### Доставка: real-time API + static fallback

**Архитектура**: `DeliveryService` — единственная точка входа для расчёта доставки.

| Компонент | Назначение |
|-----------|------------|
| `src/Service/DeliveryService.php` | Расчёт стоимости и сроков через API CDEK/Boxberry |
| `ShippingRule` (entity) | Статические правила-заглушки (цена, сроки, макс. вес, trackingUrl) |
| `CheckoutController::shippingRules` | AJAX `/checkout/shipping-rules?country=&city=&weight=` |
| `CheckoutController::confirm` | Расчёт при оформлении заказа |

**Приоритет расчёта стоимости**:
1. Live API (CDEK `/calculator/tariff` или Boxberry `DeliveryCalculation`)
2. Static rule из таблицы `shipping_rule` по ID/carrier/стране
3. Жёсткий fallback (cdek=350₽, boxberry=280₽, pochta=200₽, pickup=0₽)

**CDEK API**:
- Авторизация: OAuth2 client_credentials → Bearer token
- Тариф: 483 (Интернет-магазин, посылка)
- Параметры: from_location.address, to_location.address, packages[].weight (граммы)
- Ответ: `total_sum` (копейки → рубли), `delivery_period_min/max`

**Boxberry API**:
- `DeliveryCalculation` с token, weight, target, target_start
- Ответ: `price`, `delivery_period`

**В шаблоне checkout/index.html.twig**:
- Бейдж `LIVE` у правил с реальным расчётом
- `trackingUrl` в ShippingRule с `%s` для подстановки трек-номера
- Фильтрация по `maxWeightKg` — исключаются правила, не подходящие по весу

**Трек-номера** для заказов (ручной ввод в админке):
- `order.trackingNumber` + carrier → ссылка на отслеживание в `order_show.html.twig`

## Заметки 2026-06-12

### Tilda как конкурент (техническое исследование платежей)

**Модель Tilda — чистая SaaS-подписка, 0% с продаж, денег не касается вообще.**
- Продавец сам заключает договор с эквайером (ЮKassa/Robokassa/CloudPayments/Т-Банк и др.), вводит свои `shopId`+ключ в настройки — деньги идут напрямую на его счёт.
- Чеки/54-ФЗ/ОФД — целиком ответственность продавца; Tilda только прокидывает состав заказа в платёжку (опция «Передавать данные для чеков», ставки НДС per-товар).
- Заказы → «Заявки» (хранение 30–90 дней) + бесплатная Tilda CRM + вебхуки/Google Sheets/Telegram/amoCRM/Битрикс24.
- Цены РФ: Personal 750 ₽/мес (500 при годовой), Business 1250 ₽/мес (1000), магазин до 5к/50к товаров. Free — без платёжек, магазина фактически нет.
- **Вывод**: Tilda — валидация модели «деньги напрямую продавцу + подписка вместо комиссии» на рынке РФ. Наше отличие: Tilda продаёт инструмент без трафика («один продавец = один сайт»), WEARBASE продаёт дистрибуцию (общий каталог, SEO, RAG-контент). Но бренды будут сравнивать цену: Tilda 500–750 ₽/мес — психологический «пол» рынка. Источники: help-ru.tilda.cc/online-store/payment-systems, /payments/yookassa, /online-store/online-kassa, tilda.cc/ru/pricing.

### Ветка: парсинг Wildberries → точные поисковые фильтры

Идея: парсить товары WB, прогонять через LLM (локальная ollama — почти бесплатно), извлекать структурированные атрибуты → поиск уровня «бежевая юбка, длина >70 см, шёлк >50%».
- Технически реализуемо: у WB полупубличные JSON-эндпоинты карточек (card.wb.ru), состав/длина есть в характеристиках; LLM нужен для нормализации (состав в %, цвет, длина).
- Ценность: фасетный/семантический поиск по атрибутам — то, чего нет ни у WB, ни у Ozon (их фильтры грубые). Сильный дифференциатор + питание для LLM-видимости.
- **Напряжение с позиционированием**: мы топим за «без маркетплейсов», а ссылки с карточек вели бы на WB. Безопасный вариант: парсить WB только для брендов, уже добавленных в каталог (обогащение их товаров атрибутами + корпус для RAG), не как самостоятельную витрину чужих товаров.
- Правовой статус: серая зона (парсинг публичных данных), риск умеренный, но учитывать при масштабировании.

### Экономика подписки — сомнение

1500 ₽/мес → 10 брендов = 15к/мес, 100 брендов = 150к/мес. Ощущение: слишком много усилий/клиентов за маленькие деньги.
- Хостинг: 100 брендов — это копеечная нагрузка; выделенный сервер НЕ нужен, достаточно VPS за 1–2к ₽/мес. Хостинг не аргумент в этой математике.
- Рычаги: средний чек (Premium 3000 ₽ как якорь, допуслуги «контент/SEO под ключ» — RAG-конвейер уже делает это почти даром), годовая оплата вперёд (cash flow), и пересмотр ценности: продаём не «карточку в каталоге», а «топ выдачи по брендовому запросу + LLM-видимость» — это сравнивают с бюджетом на директ (десятки тысяч ₽/мес), а не с Tilda.
- Открытый вопрос: либо масштаб (сотни брендов, автоматизированный onboarding), либо выше ARPU (меньше клиентов × дороже), текущие 1500 ₽ — посередине и не туда и не сюда.

### Контент-маркетинг: статьи для SEO + внешние площадки

**Принцип**: канонические статьи живут в блоге на wearbase.ru (`/ru/blog/...`) — SEO-вес копится на своём домене. Дзен и VC.ru — дистрибуция, узнаваемость и ссылочный профиль, туда — адаптации со ссылкой на оригинал (или уникальные тексты, чтобы не словить дубль-контент).

**Площадки:**
- **Дзен (dzen.ru)** — охватный канал, лента Яндекса; формат: лайфстайл/подборки («10 российских брендов платьев»), трафик на карточки брендов.
- **VC.ru** — бизнес-аудитория; формат: кейсы и цифры («Сколько на самом деле забирает WB у бренда одежды», «Как мы делаем каталог без комиссии»). Хорошо индексируется, даёт упоминания для LLM-видимости.
- Резерв: Pikabu (виральные истории), Т—Ж (если возьмут), Habr (только если про RAG-конвейер технически).

**Темы статей по трём уровням запросов (из SEO-стратегии выше):**
1. Информационные (блог + VC): «Комиссии маркетплейсов 2026: полный расчёт» — ✅ написана и опубликована в блоге (`/ru/blog/komissii-marketpleysov-2026`, черновик в `docs/blog-drafts/`); лендинг `/marketplace-commissions` отдаёт на неё 301 (с fallback-рендером, пока статья не опубликована в проде). Также написаны и опубликованы (2026-06-12): «Российские бренды одежды: гид 2026» (`rossiyskie-brendy-odezhdy-gid`, флагман — кластер 13,7к показов/мес), «Почему продавцы уходят с Wildberries» (`pochemu-prodavtsy-uhodyat-s-wildberries`), «Как купить одежду напрямую от производителя» (`kak-kupit-odezhdu-napryamuyu-ot-proizvoditelya`). Все перелинкованы между собой и с каталогом. Карта ключевиков по Wordstat — `docs/seo-keywords-2026-06.md`. 2. Категорийные (блог + Дзен): подборки «N российских брендов [категория]» — генерируются полуавтоматически из каталога + RAG-фактов, каждая ссылается на карточки брендов.
3. Брендовые: статьи-обзоры отдельных брендов (Дзен) → ссылка на карточку → закрепление топа по брендовому запросу.

**Синергия с RAG**: конвейер уже собирает факты по брендам — те же чанки можно использовать для генерации черновиков подборок/обзоров (отдельная команда генерации статей, человеческая вычитка обязательна).

**Технически нужно**: блог-раздел на сайте (entity Article, роут `/{_locale}/blog/{slug}`, sitemap, schema.org `Article`) — ✅ реализован 2026-06-12 (`BlogController`, админка «Контент → Статьи блога»).

**Размещение на VC.ru — рабочая схема**: готовим статью сами → на kwork.ru находим исполнителя, который за ~1000 ₽ публикует её на VC.ru (аккаунты с историей публикуются без премодерации/отлёжки). Дёшево покупаем площадку + ссылку + упоминание для LLM-видимости. Нюансы: ссылку на wearbase.ru вшивать в тело статьи (не в подпись), статья на VC должна быть уникальной (не копией из блога), проверять у исполнителя возраст/карму аккаунта, чтобы статью не снесли.
